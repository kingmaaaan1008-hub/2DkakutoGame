# 一発当たったら即死な2D格闘

スマホ・PC 両対応のブラウザ 2D 対戦格闘ゲーム。
ビルド不要の静的サイトなので、**リポジトリをそのまま GitHub Pages に公開すれば動きます。**

- **先に技を通した方が勝ち。** 攻撃が当たった時点で体力は全部消えます
- 3 キャラクター（剣士 / 狂戦士 / 魔法使い）
- CPU 戦 / 同一端末での 2 人対戦 / オンライン対戦
- キーボード・ゲームパッド・画面タッチに対応
- 技はすべてデータ定義。技もキャラも追加しやすい構造

---

## ルール

**攻撃が当たったらその時点で負けです。** 多段技なら 1 打目でも最終打でも同じで、
かすった瞬間に勝敗が決まります。ダメージ量という概念がありません
（技データの `damage` は技の重さの目安として残してありますが、計算には使いません）。

ただし当たった瞬間に消えると何が起きたか分からないので、演出だけ最後まで見せます。

1. 当たった時点で体力を 0 にして、内部的に「致命傷（`doomed`）」を立てる
2. **のけぞりは普通に取る** — 残りの段もそのまま当たり、ヒット数が伸びていく
3. **コンボが途切れた瞬間に崩れ落ちる**

**血しぶきが出るのは 3. の崩れ落ちる瞬間だけ**です。コンボ中の 1 打 1 打は
従来どおり火花で、決着したことが一目で分かるようにしてあります。

つまり 4 段技が全部当たれば「4 HITS」まで見えてから倒れ、
1 段目だけかすったなら、そののけぞりが解けたところで倒れます。

避ける手段は **2段ジャンプ / しゃがみ / ダッシュ / ガード** の 4 つ。
**ガードは通ります**が、**スキルはガードごと崩す**ので守り一辺倒では勝てません。
**ジャンプ中も攻撃・スキルが出せます**（それぞれ専用の空中技）。

**しゃがみは魔法使いの照射ビームをくぐるための手段**です。
ビームは杖の先（足元から 156）を中心に上下 49 ＝ 地上 107〜205 を薙ぐので、
しゃがんでやられ判定が 100 まで縮めばその下を通せます。
ビームはガード不能なので、しゃがみが唯一の答えです。
沈むのにも立ち上がるのにも `CROUCH_TICKS` かかるため、読んで先に構える必要があります
（打撃は判定が低いところまで出ているので、しゃがんでも当たります）。

照射は**撃つまでに 1 秒（60 フレーム）の溜め**があり、その間ずっと
**足元に魔法陣**が回っています。これが「これから撃つ」の合図で、
見てからしゃがんでも十分間に合う長さにしてあります。
逆に言えば、魔法使いは 1 秒間まったくの無防備になります。

さらに魔法使いは、遠距離で完結させられないように 2 段階で制限しています。

- **ホーミング弾は場に 1 発まで**（`PROJECTILES.bolt.maxAlive`）。
  撃った弾が消えるか当たるまで次が出ないので、弾幕で近づけないようにはできません
- **照射を構えた瞬間、場に出ている自分の弾は消えます**
  （技データの `clearsOwnProjectiles`）。弾で足止めしてから照射、という
  重ねがけが通らないので、弾を撒くか照射を撃つかを選ぶことになります

決着が一瞬なので、1 ラウンド 45 秒・**3 本先取**にしてあります
（`src/game/constants.js` の `ROUND_TIME` / `ROUNDS_TO_WIN`）。

## 動かす

### そのまま公開する（GitHub Pages）

リポジトリの **ルート** をそのまま配信するだけです。

1. GitHub にプッシュ
2. Settings → Pages → Source を `Deploy from a branch`、ブランチを `main` / フォルダを `/ (root)` に設定
3. 数分後 `https://<ユーザー名>.github.io/<リポジトリ名>/` で遊べます

`assets/`・`src/`・`index.html`・`styles.css` があれば動きます。
`tools/`・`server/`・`node_modules/` は配信されても実害はありませんが、無くても構いません。

### ローカルで確認する

ES モジュールは `file://` では読み込めないため、簡易サーバ経由で開いてください。

```bash
npm install     # 画像変換用の sharp が入ります（ゲーム自体には不要）
npm run serve   # http://localhost:8080/
```

## 操作

| | 移動 | ジャンプ | しゃがみ | 攻撃 | スキル | ガード |
|---|---|---|---|---|---|---|
| **1P キーボード** | `A` / `D` | `W` | `S` | `J` | `K` | `L` |
| **2P キーボード** | `←` / `→` | `↑` | `↓` | `,` | `.` | `/` |
| **ゲームパッド** | スティック・十字 | `Y` | 十字下・スティック下 | `A` | `X` | `B` / `L1` |
| **スマホ** | 画面左の ◀ ▶ | ジャンプ | しゃがみ | 攻撃 | スキル | ガード |

- **ダッシュ**: 同じ方向を素早く 2 回押す
- **ジャンプは自分の身長ぶん跳べます**（`jumpVyForHeight()` で各キャラの身長から逆算）
- **2段ジャンプ**: 空中でもう一度ジャンプ。方向を入れずに跳ぶと真上へ跳び直して軌道をずらせます。
  2段目は高さを稼ぐためではなく軌道をずらすためのものなので、1段目より低く跳びます
- **しゃがみ**: 押している間だけ沈み、離すと立ち上がります。移動はできません。
  やられ判定は姿勢に合わせて少しずつ縮むので、押した瞬間にビームをくぐれるわけではありません
- **歩き中は常に相手を向きます。** 後ろに下がるときは歩きモーションが逆再生されます
- **ダッシュ中だけは進んでいる方向を向きます**
- **スキル**はガードを崩せる技。当たれば大きいですが、外すと隙が大きい
- **空中で攻撃 / スキル**を押すと専用の空中技が出ます。空中技は**着地した時点で打ち切られ**、
  技ごとに決めた着地硬直（`landLag`）に入ります
- `Esc` ポーズ / `F1` 判定ボックス表示（技の調整用）

### キャラクターと技

| キャラ | 攻撃 | スキル（ガード崩し） | 空中攻撃 | 空中スキル |
|---|---|---|---|---|
| **剣士** | 横切り → 続けて攻撃で **盾切り** | タックル（溜めてから突進） | 飛び斬り | 急降下斬り |
| **狂戦士** | 乱舞（4 段の連続斬り） | 突き（長い踏み込み） | 空中乱舞（2 段） | かかと落とし |
| **魔法使い** | ホーミング弾（場に**1発**まで） | 極太照射ビーム（**1秒溜め**） | 降魔弾（斜め下へ撃ち落とす） | 浮遊照射（**1秒溜め**） |

剣士と狂戦士の空中スキルは斜め下へ落ちる突進技で、外すと着地の隙が大きくなります。

魔法使いの**浮遊照射**だけは毛色が違い、**空中でぴたりと止まって**極太ビームを撃ちます。
止まる高さは「跳んでから何フレーム目に押したか」でそのまま決まるので、

- **低空で撃つ** → 地上の相手を薙ぎ払う
- **高めで撃つ** → 飛んできた相手を撃ち落とす

という撃ち分けになります。そのぶん、外すと空中に静止した的になります。

### 血しぶきの作り方（`renderer.js`）

決着の演出なので、ここだけは作り込んであります。安っぽく見えないために効いているのは
主に次の 4 つで、いずれも `_drawBlood` / `_bloodParticles` の中にあります。

| | やっていること | これが無いと |
|---|---|---|
| **粒径をべき分布に** | `0.32 + u^4.6 * 3.1`。ほとんどが微細な粒で、大粒はごく少数 | 同じ大きさの丸が並んで、一気に嘘くさくなる |
| **空気抵抗** | `dv/dt = -k・v - g` の解析解で飛ばす。`k` は粒径に反比例 | 全部が同じ形の放物線を描く。抵抗があると小粒はその場に落ち、大粒だけが遠くまで届く |
| **着地したら床の染みに** | 着地時刻を粒ごとに先に解いておき、以降は染みとして描く | 落ちた血が消えてしまう |
| **加算合成を使わない** | `source-over` の暗い静脈血。薄く伸びた部分だけ少し明るく | 血が光る。光った瞬間に嘘になる |

粒ごとの初期値は描画側の `WeakMap` に持っています。エフェクト自体
（＝シミュレーションのデータ）には書き戻さないので、ロールバックしても壊れません。
飛沫が一番多いフレームでも `render()` は約 4.8ms（60fps の予算 16.7ms）です。

### 設計の要点

**ゲームのルールは `src/game/` に閉じています。** ここは

- 実時間（`Date.now` / `performance.now`）を見ない
- `Math.random` を使わない（乱数は `core/rng.js` 経由）
- 画像サイズなど描画側のデータに依存しない

を守っているため、**同じ入力列からは必ず同じ試合になります**。
この性質があるおかげで、CPU 戦・ローカル対戦・オンライン対戦・リプレイを
すべて同じコードで扱えます。

## 技・キャラを追加する

### 技を足す

`src/game/characters/*.js` の `moves` にデータを 1 つ足すだけです。
状態遷移のコードには手を入れません。

```js
uppercut: {
  label: '昇竜',
  anim: 'attack2',        // アトラスのアニメ名
  total: 44,              // 全体フレーム（60fps）
  animFps: 14,            // 省略すると total に引き伸ばして再生
  hits: [{
    start: 8, end: 14,                        // 判定が出る区間（両端含む）
    box: { x: 20, y: 60, w: 120, h: 170 },    // 足元原点・前方向が正・上が正
    hitstun: 30, hitstop: 10,                 // damage は不要（当たれば即死）
    launch: { y: 11 },                        // 打ち上げる
  }],
  motion: [{ start: 6, end: 14, vy: 12 }],    // 自分の移動
  chains: [{ from: 20, to: 38, button: 'attack', move: 'finisher' }], // 連携先
},
```

空中技は、キャラ定義の `airAttackMove` / `airSkillMove` に技 id を書けば
ジャンプ中のボタンに割り当たります。着地で打ち切られるので、
`landLag` で外したときの隙を決めてください。

主なフィールドは `src/game/moves.js` の先頭にまとめてあります。
`F1` で判定ボックスを表示しながら調整すると早いです。

必殺技コマンド（`↓↘→` など）を足したくなったら、`Fighter._readInput` に
入力履歴の照合を追加し、技データ側に `command` を持たせる形になります。
入力はすでにフレーム単位のビットマスクで扱っているので、履歴を見るだけで実装できます。

### キャラを足す

1. スプライトシートを `SpriteSheetCreater` で出力する
2. `tools/build-assets.ps1` の `$CONFIG` に追加する
3. `npm run assets` を実行
4. `src/game/characters/新キャラ.js` を作り、`characters/index.js` の `ROSTER` に足す

## アセットのビルド

元のスプライトシートは 1 枚 4〜14MB あり、合計 40MB 近くあります。
そのままでは（特にスマホで）重いので、2 段階で加工しています。

```bash
npm run assets          # 生成（PowerShell + Node）
npm run assets:verify   # 整列を目視確認する画像を .debug に出力
```

| 段階 | スクリプト | やること |
|---|---|---|
| 1 | `tools/build-assets.ps1` | アニメごとに余白を切り詰め、縮小し、1 キャラ 1 枚のアトラスに詰め直す。**アニメごとにアンカー（足元の位置）を計算して JSON に書く** |
| 2 | `tools/pack.mjs` | WebP に変換（PNG 12.4MB → **2.8MB**） |

1 キャラは複数のシートに分かれています（例: `swordsman` / `swordsman_extra` /
`swordsman_crouch`）。シートを増やしたら `tools/build-assets.ps1` の `$CONFIG` の
`sheets` に 1 行足してください。中のアニメは自動で全部拾われます。

**アンカーが要点です。** 通常シートと `_extra` / `_crouch` シートではコマ寸法が
違い（485×485 と 560×614 など）、キャラの描かれている位置もずれています。
そのまま並べると、ガードした瞬間にキャラが浮いたり横にずれたりします。
そこで各シートについて

- **接地ライン**: 行ごとの不透明ピクセル数から足の裏を検出（下に垂れた刃先やマントを無視する）
- **左右位置**: シルエットのアルファ加重中央値（外に伸びた剣に引っ張られない）

を求め、その点を基準に全アニメを描き直しています。実測ではキャラの実寸は
シート間で 2% 以内に収まっていたので、拡大縮小の補正は不要でした。

元シートの場所を変えた場合は `-Src` で指定できます。

```bash
powershell -ExecutionPolicy Bypass -File tools/build-assets.ps1 -Src D:\path\to\output_sprite
node tools/pack.mjs
```

## テスト

```bash
npm test
```

ブラウザを使わず、シミュレーションに入力を流し込んで検証します（116 件）。
移動・ダッシュ・連携・ガード・ガード崩し・飛び道具・ラウンド進行に加え、

- **照射の 1 秒溜め**（溜め中は無害 / 魔法陣が出る / 溜めきると入力無しで照射へ移る）

- **ジャンプ高**（3 キャラとも自分の身長ぶん跳べる）
- **2段ジャンプ**（3 回目は跳べない・着地で回数が戻る）
- **空中攻撃と空中スキル**（着地で打ち切られる・着地硬直に入る）
- **同じ入力から同じ試合になること**と **`save()`/`load()` で巻き戻せること**
  （オンライン対戦の前提）

も確認しています。

## オンライン対戦

ゲーム本体は静的ファイルだけで完結しますが、オンライン対戦のときだけ
**中継サーバ**が必要です。詳細は [`server/README.md`](server/README.md)。

```bash
cd server && npm install && npm start   # ws://localhost:8787
```

タイトル →「オンライン対戦」→ キャラ選択 → サーバ URL と合言葉を入力。
同じ合言葉の 2 人が繋がると試合が始まります。

判定やダメージ計算はサーバでは**行いません**。2 台のブラウザが同じ入力から
まったく同じシミュレーションを走らせます。サーバの仕事は
「2 人を組ませる」「乱数シードを配る」「入力を横流しする」の 3 つだけなので、
安いレンタルサーバでも十分です。

> GitHub Pages は https 配信のため、接続先は **`wss://`（TLS）が必須**です。
> nginx などでリバースプロキシして TLS を終端してください。

### 通信方式を差し替える

現在は**入力遅延ロックステップ**（`src/net/session.js` の `LockstepSession`）です。
実装が小さく確実ですが、回線遅延がそのまま操作感に出ます。

ロールバックへ移行する足場はすでにあります。

- `Simulation.save()` / `load()` — 状態の巻き戻し
- `Fighter.save()` / `load()` — 素の値だけのスナップショット
- シミュレーションが実時間・`Math.random` に依存していないこと

`LockstepSession` を差し替えるだけで済み、ゲームのルールには手を入れません。
WebRTC の P2P にしたい場合も、`src/net/transport.js` に同じ形のクラスを足すだけです。

## 既知の制限

- **2 人対戦（同一端末）はキーボード / ゲームパッド向け**です。仮想パッドは 1P のみを操作します
- **しゃがみ専用の技はありません**。しゃがみからボタンを押すと立ち技が出ます
  （しゃがみ攻撃のスプライトシートが用意できたら、`crouchAttackMove` を足す形で追加できます）
- 必殺技コマンド入力は未実装（上の「技を足す」参照）
- 効果音・BGM はありません
- WebP を使っているため、2020 年より前のブラウザでは画像が表示されません
