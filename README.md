# 一発当たったら即死な2D格闘

スマホ・PC 両対応のブラウザ 2D 対戦格闘ゲーム。
ビルド不要の静的サイトなので、**リポジトリをそのまま GitHub Pages に公開すれば動きます。**

- **先に技を通した方が勝ち。** 攻撃が当たった時点で体力は全部消えます
- 10 キャラクター（剣士 / 狂戦士 / 魔法使い / 女子高生 / 淫魔 /
  キャヴァリア / 忍者 / 戦闘メイド / 巫女 / 格闘娘）
- アーケード（CPU 勝ち抜き）/ CPU 戦 / 同一端末での 2 人対戦 / オンライン対戦
- キーボード・ゲームパッド・画面タッチに対応
- 技はすべてデータ定義。技もキャラも追加しやすい構造

## ルール

**攻撃が当たったらその時点で負けです。** 多段技なら 1 打目でも最終打でも同じで、
かすった瞬間に勝敗が決まります。ダメージ量という概念がありません
（技データの `damage` は技の重さの目安として残してありますが、計算には使いません）。

ただし当たった瞬間に消えると何が起きたか分からないので、演出だけ最後まで見せます。

1. 当たった時点で体力を 0 にして、内部的に「致命傷（`doomed`）」を立てる
2. **のけぞりは普通に取る** — 残りの段もそのまま当たり、ヒット数が伸びていく
3. **コンボが途切れた瞬間に崩れ落ちる**

**血しぶきが出るのは 3. の崩れ落ちる瞬間だけ**です。コンボ中の 1 打 1 打は
従来どおり火花で、決着したことが一目で分かるようにしてあります。

つまり 4 段技が全部当たれば「4 HITS」まで見えてから倒れ、
1 段目だけかすったなら、そののけぞりが解けたところで倒れます。

避ける手段は **2段ジャンプ / しゃがみ / ダッシュ / ガード** の 4 つ。
**ガードは通ります**が、**スキルはガードごと崩す**ので守り一辺倒では勝てません。
**ジャンプ中も攻撃・スキルが出せます**（それぞれ専用の空中技）。

ただし**淫魔の吸血とキャヴァリアの串刺しは掴み技**で、避け方が他と違います。

- 他のスキルはガードを崩す打撃なので、判定さえ届けば**空中の相手にも当たります**
- **掴みは相手が空中にいると絶対に当たりません**（`hit.grab`）。
  ガードでは防げないので、**跳ぶことが唯一の答え**になります

つまりこの 2 人が相手のときだけ「ガードで固めて待つ」が成立しません。詳しくは
[キャラクターと技](#キャラクターと技) の淫魔・キャヴァリアの項を見てください。

**しゃがみは魔法使いの照射ビームをくぐるための手段**です。
ビームは杖の先（足元から 156）を中心に上下 49 ＝ 地上 107〜205 を薙ぐので、
しゃがんでやられ判定が 100 まで縮めばその下を通せます。
ビームはガード不能なので、しゃがみが唯一の答えです。
沈むのにも立ち上がるのにも `CROUCH_TICKS` かかるため、読んで先に構える必要があります
（打撃は判定が低いところまで出ているので、しゃがんでも当たります）。

照射は**撃つまでに 1 秒（60 フレーム）の溜め**があり、その間ずっと
**足元に魔法陣**が回っています。これが「これから撃つ」の合図で、
見てからしゃがんでも十分間に合う長さにしてあります。
逆に言えば、魔法使いは 1 秒間まったくの無防備になります。

さらに魔法使いは、遠距離で完結させられないように 2 段階で制限しています。

- **ホーミング弾は場に 1 発まで**（`PROJECTILES.bolt.maxAlive`）。
  撃った弾が消えるか当たるまで次が出ないので、弾幕で近づけないようにはできません
- **照射を構えた瞬間、場に出ている自分の弾は消えます**
  （技データの `clearsOwnProjectiles`）。弾で足止めしてから照射、という
  重ねがけが通らないので、弾を撒くか照射を撃つかを選ぶことになります

決着が一瞬なので、1 ラウンド 45 秒・**3 本先取**にしてあります
（`src/game/constants.js` の `ROUND_TIME` / `ROUNDS_TO_WIN`）。

## 動かす

### そのまま公開する（GitHub Pages）

リポジトリの **ルート** をそのまま配信するだけです。

1. GitHub にプッシュ
2. Settings → Pages → Source を `Deploy from a branch`、ブランチを `main` / フォルダを `/ (root)` に設定
3. 数分後 `https://<ユーザー名>.github.io/<リポジトリ名>/` で遊べます

`assets/`・`src/`・`index.html`・`styles.css` があれば動きます。
`tools/`・`server/`・`node_modules/` は配信されても実害はありませんが、無くても構いません。

### ローカルで確認する

ES モジュールは `file://` では読み込めないため、簡易サーバ経由で開いてください。

```bash
npm install     # 画像変換用の sharp が入ります（ゲーム自体には不要）
npm run serve   # http://localhost:8080/
```

## 操作

| | 移動 | ジャンプ | しゃがみ | 攻撃 | スキル | ガード |
|---|---|---|---|---|---|---|
| **1P キーボード** | `A` / `D` | `W` | `S` | `J` | `K` | `L` |
| **2P キーボード** | `←` / `→` | `↑` | `↓` | `,` | `.` | `/` |
| **ゲームパッド** | スティック・十字 | `Y` | 十字下・スティック下 | `A` | `X` | `B` / `L1` |
| **スマホ** | 左半分を横へ小さく/大きく | 左半分を上/斜め上（空中はどの向きでも） | 左半分を下 | 右半分をタップ | 右半分を敵の方へ | 右半分を下 |

- **ダッシュ**: 同じ方向を素早く 2 回押す（スマホは横に大きくスワイプ）
- **ジャンプは自分の身長ぶん跳べます**（`jumpVyForHeight()` で各キャラの身長から逆算）
- **2段ジャンプ**: 空中でもう一度ジャンプ。方向を入れずに跳ぶと真上へ跳び直して軌道をずらせます。
  2段目は高さを稼ぐためではなく軌道をずらすためのものなので、1段目より低く跳びます
- **しゃがみ**: 押している間だけ沈み、離すと立ち上がります。移動はできません。
  やられ判定は姿勢に合わせて少しずつ縮むので、押した瞬間にビームをくぐれるわけではありません
- **歩き中は常に相手を向きます。** 後ろに下がるときは歩きモーションが逆再生されます
- **ダッシュ中だけは進んでいる方向を向きます**
- **スキル**はガードを崩せる技。当たれば大きいですが、外すと隙が大きい
- **空中で攻撃 / スキル**を押すと専用の空中技が出ます。空中技は**着地した時点で打ち切られ**、
  技ごとに決めた着地硬直（`landLag`）に入ります
- `Esc` ポーズ / `F1` 判定ボックス表示（技の調整用）

### スマホはボタンではなくスワイプ

画面を左右に割って、**左半分が移動・右半分が攻撃**です。ボタンは置いていません。
押す場所を目で探す必要がなく、画面のどこを触っても効くので、視線をキャラから外さずに操作できます。

| 左半分（移動） | | 右半分（攻撃） | |
|---|---|---|---|
| 横に**小さく**スワイプ | 歩く | **タップ** | 攻撃 |
| 横に**大きく**スワイプ | 走る | **相手のいる方へ**フリック | スキル |
| 斜め上スワイプ | 斜めジャンプ | 下へフリック | ガード |
| 真上スワイプ | 垂直ジャンプ | | |
| 下スワイプ | しゃがみ | | |
| **空中はどの向きでも** | 2段ジャンプ | | |
| **滞空中の横スワイプ** | そのまま横へ飛ぶ | | |

- **指を触れている間、その入力が続きます**（離すと止まる）。走りも同じで、
  指を置いたままなら技や被弾で途切れても走りに戻ります
- **指を離さずに続けて操作できます。** 弾いて指を戻せば次のスワイプを受け付けるので、
  「歩いてから走りに上げる」も「走ったまま上へ弾いて斜めジャンプ」も 1 タッチで繋がります
- **空中ではどの向きへ弾いても 2段ジャンプ**になります。横へ弾けばその方向へ跳ぶので、
  真上を狙う必要はありません。空中では横入力で速度が変わらない
  （跳んだ瞬間の向きで軌道が決まる）ので、横スワイプをそのままにしておくと
  空振りになるためです。空中の移動手段はジャンプだけ、という前提に合わせています
- **ただし淫魔の滞空中だけは、横スワイプがそのまま横移動**になります。滞空は
  横入力が直接そのときの速度になるので、地上と同じく「触っている間ずっとその向きへ」
  で動かせます。ここをジャンプ扱いにすると、横へ動かすたびに飛行の残り回数が減り、
  撃ち止めると横に動けなくなります。高さを取り直す上・斜め上のスワイプは滞空中も跳びます
- **1 回の弾きで跳ぶのは 1 回だけ**です。指はまっすぐ動かないので、斜めに弾くと
  弧を描いて後半が別の向きへ流れ、そこが新しいスワイプとして拾われます。
  空中ではどの向きへ弾いても跳ぶため、そのぶんまで跳ばせると
  **斜めジャンプのつもりで 2段ジャンプまで消える**ことになります。
  指を戻して弾き直せば（＝新しい弾き）また跳べるので、続けて跳ぶ操作は塞いでいません
- **左右は同時に使えます**（左の親指で走りながら右の親指で技）
- **攻撃は指を離した時点で出ます。** 押した瞬間に出す方が速いのですが、
  それだとスキルやガードのスワイプも「まず押す」ので毎回攻撃が暴発します。
  一撃で決まるゲームなので、暴発の方が数フレームの遅延より痛いという判断です。
  同じ理由で、**弾いた後に指を離しても攻撃は出ません**（タップとは区別しています）
- 置きっぱなしの指を離しただけで技が出ないよう、タップと見なす接触時間には
  上限（`TAP_MAX_MS`）があります
- スキルが**左右ではなく前後**で決まるのは、相手が回り込んでも
  「フリックした向き」と「出る技」が食い違わないようにするためです。
  相手に背を向ける方向のフリックは割り当てていません
- いま何が入っているかは画面下のラベルに出ます。何もしていない間は操作の凡例が薄く出ます

**認識に使っているのは向きと距離だけで、速さは見ていません。**
ゆっくり滑らせても素早く弾いても同じ扱いになります（「スワイプ」と「フリック」で
挙動は変わりません）。速さを条件にすると「強く弾いたつもりが出ない」が起きやすく、
一撃で決まるこのゲームでは取りこぼしの方が痛いためです。

判定値は `src/core/gestures.js` の `SWIPE` に集めてあります。角度は横を広く
（各 90°）・真上と真下を狭く（各 60°）取ってあり、横に大きく弾いて指が弧を描いても
走りとして扱われます。歩きと走りの境目は `RUN`（弾いた距離）です。

剣士と狂戦士の空中スキルは斜め下へ落ちる突進技で、外すと着地の隙が大きくなります。

**女子高生は自分の技に打撃判定をひとつも持ちません。** 当てるのはスマホから出る
レーザーと、スキルで呼ぶ彼氏だけです。「技を出す」と「当たる」が離れているのが持ち味で、
弱点でもあります。

- **カメラレーザー**は追尾しないぶん速く、真っ直ぐ飛びます。発射位置は
  **掲げたスマホのカメラ**（足元から x=58 / y=170）で、スマホ本体の前端より
  少し先に置いてあります（本体の中心から出すと光が被って手元が潰れます）。
  頭の高さを薙ぐので、**しゃがめばくぐれます**
- **彼氏突進**は、指をさすと**後ろ 300 から彼氏が走ってきて**相手に突っ込みます。
  呼んでから届くまでが長いぶん、当たればガードごと崩してダウンを奪います。
  **当てても消えず、そのまま走り抜けていきます**（判定は一度当てたところで切れるので、
  走り抜けながら何度も当たることはありません）。外しても走り抜けるだけで、
  その間こちらは丸腰です。彼氏は場に 1 人までなので連呼できません。
  **空中で呼んでも彼氏は地面を走ります**（`groundBound`）

彼氏は飛び道具の枠（`PROJECTILES.boyfriend`）で動かしていますが、`style: 'sprite'` を
持つので専用のアトラス（`assets/characters/boyfriend.*`）で描かれます。
判定も丸ではなく人ひとりぶんの箱です（飛び道具の `box`）。
走りから突進への切り替えは**相手との距離**で決めています（`tackleRange`）。
経過フレームで切り替えると、呼んだ位置によって跳び込む間合いがずれてしまうためです。

**突進のシートは 1 回ぶんの動きなので、繰り返しません。** 切り替えは距離で決めますが、
**コマ送りは距離ではなく、突進に入ってからの経過フレーム**（`lungeAge`）で進めます。
コマまで距離で決めると、相手を追い越したあとに距離が開いてコマが逆戻りし、
2 周したように見えてしまいます。出し切ったら走りに戻って、そのまま走り抜けます。

#### レーザーの描き方（`_drawLaser`）

血しぶきとは逆に、**ここは加算合成が正しい**判断になります。血は光らないので
`source-over` で描いていますが、レーザーは光そのものなので、背景に足し合わさらないと嘘になります。

| | やっていること | これが無いと |
|---|---|---|
| **断面を楕円の放射グラデーションに** | 単位円のグラデーションを長円へ引き伸ばす | 帯を重ねると段が見えて「板」になる |
| **芯を丸端の線で描く** | `lineCap: 'round'` の 1 本線 | 端が角ばって、切り落とした棒に見える |
| **芯だけ白く飛ばす** | 中心の彩度を捨てて白にする | 明るいだけの色帯になる。強い光は白飛びする |
| **進行方向へ伸ばして向ける** | 1 フレーム進む距離ぶん尾を引き、速度ベクトルの角度に回す | 止まって見える／斜めに撃っても光は水平のまま、という食い違いが出る |
| **尾を発射点より後ろへ伸ばさない** | 飛んだ距離を上限にする | 撃った直後に長い尾が出て、スマホと手に光が被る（＝そこから出ているように見えない） |

判定そのものは軸に沿った箱のままなので、斜めに撃ったときは見た目と判定が
厳密には一致しません（見た目を優先しています）。

魔法使いの**浮遊照射**だけは毛色が違い、**空中でぴたりと止まって**極太ビームを撃ちます。
止まる高さは「跳んでから何フレーム目に押したか」でそのまま決まるので、

- **低空で撃つ** → 地上の相手を薙ぎ払う
- **高めで撃つ** → 飛んできた相手を撃ち落とす

という撃ち分けになります。そのぶん、外すと空中に静止した的になります。

#### 淫魔（掴みと飛行）

剣士・狂戦士・魔法使い・女子高生が「ガードは崩せるが、跳ばれると弱い」で揃っているのに
対して、淫魔は逆を向いています。**ガードに勝って、ジャンプに負ける**キャラです
（同じ性質の掴みはキャヴァリアの串刺しにもあります）。

**吸血（掴み）** は判定に `grab: true` を持つ技で、他の攻撃とは別の経路を通ります。

- **ガードを見ません。** 固めている相手にもそのまま通ります
- **相手が空中にいると当たりません**（`sim.js` の `_resolveHits`）。
  跳ぶことが唯一の回避手段です
- 捕らえると `onHit` で保持の技（`drainHold`）へ移り、相手は `STATE.GRABBED` になります。
  位置・向きとも固定され、**掴んだ本人以外からは無敵**です
- 吸い切ると最後の 1 打で放り投げ、叩きつけたところで決着します。
  掴んだ側が途中で技を中断されると、相手はその場で落とされます
- **外すと総フレームぶん硬直します。** 掴みは当たれば決まりなので、
  リスクは全部「外したとき」に寄せてあります

保持位置は技データの `grabHold`（足元原点・前方向が正）で決めます。掴まれた側は
各キャラの `grabbed` アニメで描かれるので、**ロスター全員が `anims.grabbed` を持つ必要**が
あります（同キャラ戦があるので淫魔自身も含む）。描画は y 順ではなく
**掴まれている側を必ず手前に**描いています（`renderer.js`）。
吸血は相手に顔を埋めて吸う画なので、淫魔の顔が相手の陰に入るのが正しい姿です。

**飛行**はキャラ定義の `flight` で表します。

```js
airJumps: 4,                                  // 1段目(地上)と合わせて 5 段
flight: { fromJump: 3, ticks: 42, speed: 3.8 },
```

- **1・2 段目は他のキャラと同じ跳び上がり**です
- **3 段目から先は跳び上がらず、その高さに留まります**（`ticks` フレーム）。
  左右入力があれば `speed` でその高さのまま動けます
- **高度は上がりません。** 高さを稼ぐのはあくまで 1・2 段目で、
  飛行は「跳んだ高さを保ったまま位置を選び直す」ための手段です
- 技を出すと滞空は切れます。滞空 → 急降下、という繋ぎが主な使い道です
- スマホでは滞空中だけ横スワイプがジャンプではなく横移動になります
  （`InputManager.hovering`）。滞空は横入力が直接そのときの速度になるので、
  空中の他の場面と違って「押しっぱなしが効く」ためです

重力の打ち消しは、滞空中は毎ティック `vy` を 0 に戻すだけで済ませています
（`_integrate` はそのあとに走るので、落下ぶんが積もりません）。
魔法使いの浮遊照射が使っている技データの `vy: 0` と同じ考え方です。

#### キャヴァリア（切り抜けと横の突進）

**間合いを詰める技を別に持ちません。** 攻撃そのものが切り抜けで、
振る＝踏み込むになっています。「近づいてから振る」ではなく
**「振れる位置に来た瞬間に振り切る」**キャラで、置き技として振ると
自分から相手の前へ飛び込むことになります。

代わりに、どの技も真っ直ぐで長い一本の線を引きます。読まれた側は下がる必要がなく、
跳ぶかガードして待てば通り過ぎたところを差し返せます。淫魔がガードに勝って
ジャンプに負けるのに対して、こちらは**距離に勝って、待ちに負ける**キャラです。

- **切り抜け**は判定リーチ 156 に踏み込み 121 が乗るので、実効射程は剣士の横切りより
  ひと回り長くなります。**空振りは相手の目の前で止まる**ので、届く位置に来た瞬間に
  振り切る技です。通り抜けざまに**刃を 4 回擦り付けてから振り抜く** 5 段で、
  刻みの間隔は 6 フレームおき（判定 3 フレーム＋ヒットストップ 3 フレーム）です
- 攻撃ボタンを押し直すと、斬らずに**斜め後ろ上へ跳び退きます**（後退ブースト）。
  1 段目は振り切ると相手の目の前で止まる技なので、これがその後始末です。
  **攻撃判定は持たず**、当てても外しても同じだけ下がれるので、
  「振って、通っても通らなくても引く」が 1 セットで組めます。
  受付が開くのは**1 段目の判定が終わってから**なので、連打しても振りが途中で切れません
  （剣士の 2 段斬りと同じ作りです）
- 後退ブーストからは、**スキルで錐揉み突進へ繋がります**。跳び退いた高さがそのまま
  突進の高さになるので、**切り抜け（前）→ 後退（後ろ上）→ 突進（前）**と
  折り返しながら詰め直せます。跳んでから出すのと違って高度は選べません
- **空中攻撃は地上とまったく同じ技**（`airAttackMove` が `attackMove` と同じ id）です。
  attack5 シートがもともと「飛びながら斬り抜ける」絵なので、地上でも空中でも通ります。
  空中では技データの `vy: 0` が効いて、**その高さを保ったまま横へ抜けます**
- **串刺し**は淫魔の吸血と同じ掴み（`grab: true`）です。二刀で貫いて持ち上げ、
  締めの 4 段で刃ごと押し込んで放り捨てます。掴みとしては異例に長い射程の代わりに、
  発生 18・空振りの戻り 26 と、外したときの隙も一番大きくしてあります
- **錐揉み突進**は全キャラで一番長く横へ動く技（248）で、回っている刃で
  5 回削ってから弾き飛ばす 6 段です。**突進中にもう一度スキルを押すと
  宙返りで降りられます**（`chains` で `boostDrop` へ切り替え）。降りる技は
  **攻撃判定を持ちません**。突っ込む距離と降りる位置を切り離すためのものです

切り抜けの絵は、技データの `animDelay` で **1 枚目を 22 フレーム据え置いてから**
残りを一気に流しています。構えたまま刃を擦り付けて滑り込み、判定が切れるあたり
（判定は 8〜24）でようやく振り抜かれる、という見せ方です。素直に頭から流すと、
突っ込んでいる最中にもう振り終わっていて、一番長く見えている絵が
「振り終わりの余韻」になってしまいます。

**多段はダメージのためではなく手応えのためにあります。** 一発が即死なので、
2 発目以降が勝敗を変えることはありません。1 発ごとに火花とヒットストップが入って
HIT カウントが伸びるぶんだけ、当てたことが分かりやすくなります（狂戦士の乱舞と同じ）。
組み方には決まった型があって、

- 刻みは押し出しをほとんど付けない。飛ばすのは締めの 1 発だけ
- **刻みに `knockdown` を付けない。** ダウンさせるとその時点で無敵になり、
  2 発目以降が素通りします（錐揉み突進の締めだけがダウンを奪います）
- **掴みの拘束中は殴れない。** 掴んだ相手を打つと `receiveHit` がその場で手を離すので
  （`grabbedBy = -1`）、串刺しの多段は「放すとき」にまとめてあります。
  1 発目で手が離れ、残り 3 発が宙に浮いた相手を追い撃ちします
- 錐揉み突進だけは**当てたら食い込ませる**必要があります。9.2 のまま突き抜けると
  2〜3 発目で相手を追い越してしまうので、`motion` に遅い区間を先に書き、
  速い区間に `stopOnHit` を付けて「当てたあとは遅い方だけが残る」ようにしています
  （空中では横の勢いが自然に落ちないので、`stopOnHit` だけでは止まりません）

後退ブーストが斜め上へ跳ぶということは、空中で攻撃を連打すると上がり続けかねない
ということでもあります。**跳んだぶんを重力で返し切る長さ**（全体 42 / 移動は 24 まで）に
してあるので、繰り返しても高度は稼げません。`npm test` がここを見張っています。

##### スラスターの粒とビームの弧

このキャラだけ、**光の粒を撒きます**（`src/render/sparkles.js`／キャラ定義の
`thruster` を持つキャラだけ）。粒は 2 系統あります。

- **排気**: 速く動いている間だけ出るぶん。噴射口を技ごとには書いていません。
  立ち・ジャンプ・水平の錐揉みで姿勢がまるで変わるので、**そのときの速度から
  「体の中心の少し後ろ」を噴射口にする**決め方にしてあります。排気は進行方向の
  逆へ流れるものなので、これでどの姿勢でも筋が通ります。歩き（3.0）では出ず、
  錐揉み（9.2）で最大になるので、**粒の量がそのままブーストの手がかり**になります
- **常時**: 止まっていても背中から漏れ続けるぶん。速度ではなく**向き**で位置が
  決まります（背中側は前方向の逆なので x が負）。スラスターに火が入りっぱなしで
  あることを見せておくと、待機中でも機体が生きている感じになります

噴射口の位置はどちらも実測で決めています。

- **排気**は足元から 150 の高さ。速く動いているときに使う絵（`move` / `jump` /
  `attack2` / `attack5`）はどれも体が浮いていて、翼は 110〜180 のあたりに来ます。
  立ち姿勢に合わせて 118 にしていたときは、ダッシュ中に足元から湧いて見えました
- **常時**は腰の高さの、**翼が二股に分かれるところ**（x = -54 / y = 134）。
  立ち姿勢の実測で、翼は y ≒ 145 より上では 1 本、そこから下は 2 本に割れます
  （y = 130 の断面が外側 -70〜-48 ／ 内側 -37〜-20 の 2 本）

**描く順番は 2 系統で分けています。** 排気はキャラより奥（後ろへ流れていくものなので
体に隠れる側が正しい）、常時のぶんはキャラより手前です。常時のぶんの噴射口は
翼の分岐点なので、奥に描くと必ず翼の陰に入って一粒も見えません。

粒は `sim.effects` ではなく**描画側だけ**が持っています。演出の 1 個 1 個を
ロールバックの対象にすると、巻き戻すたびに粒の配列まで保存・復元することになって
割に合わないからです。フレームを落としても粒が減るだけで、勝敗もリプレイもずれません。

##### 薄れるビームサーベルを持ち上げる

元シートの刃には薄いコマがあり、**原因が 2 つ**あります。片方だけ直しても直りません。
素材の作り直しでも直りませんでした。AI で描いた絵なので、描き直しても同じ癖が出ない
保証がありません。

| | 症状 | 実測 |
|---|---|---|
| 画素の量 | 振りの速いコマほど刃が細く短い | 切り抜け f0 3651 → f7 1733（47%）、串刺し f0 2569 → f3 1030（40%） |
| 画素の透明度 | 刃そのものが半透明で**背景が透ける** | 串刺し f2 は 34% が alpha 200 未満、下位 1/4 は alpha 152 |

透ける側は**加算合成では絶対に直りません**。加算は背景に光を足すだけで背景を隠さないので、
いくら強くしても「明るいが透けている」にしかならず、光だけが強くなって白飛びします。
`lighter` だけで押し切ろうとして失敗したのがこれでした。

そこで発光層（`src/render/beamglow.js`）は**本体の下に敷きます**。アトラスから
「ビームらしい色の画素」だけを抜き出したレイヤーを焼くところは同じで、緑と青が揃って高く、
赤からはっきり離れている画素だけを拾うので、白い装甲（r≈g≈b）も濃紺の翼（緑が低い）も
引っかかりません。効いているのは次の 3 つです。

1. **下に敷く**（`backing`／`source-over`）。本体より先に不透明な光を置くので、
   半透明の刃が透けた先に出るのが背景ではなく光になります。敷くほうが 1/3 でぼけていても
   構いません。**上に本物の刃が乗るので、見えるのは輪郭からはみ出したぶんだけ**で、
   それは暈として正しく見えます
2. **コマごとの正規化**（`maxGain`）。焼くときにコマの持つビーム量を測り、
   薄いコマほど強く光らせます。基準は上から 1/4 のコマで、一番濃いコマに揃えると
   たまたま刃が大写しになった 1 コマに全体が引きずられます
3. **焼き込んだ暈**（`halo`）。刃のまわりへ光をぼかして広げます。ビームが
   ビームに見えるのは**芯ではなく光**なので、刃が 1 画素まで細ったコマでも、
   まわりの光が同じ大きさで残っていれば振られているように見えます

加算合成（`alpha`）は**艶を添えるだけ**に落としてあります。裏当てで刃はもう不透明なので、
ここを上げても眩しくなるだけです。明るさの頭打ちがビームの色で止まるぶん、
`source-over` のほうが白飛びしません。

正規化の効き目は、コマ間の振れ幅（最小 / 最大）が **切り抜け 45% → 72%**、
**串刺し 43% → 71%**。もともと揃っているアニメ（錐揉み 91%、立ち 97%）は
そのままで、薄いコマだけが上がります。

ぼかしは**コマの矩形の中で閉じて**います。アトラスはコマが横に並んでいるので、
ページ全体でぼかすと隣のコマの刃が滲み出します。箱ぼかしは**3 回**通します。
2 回だと四角い段が見えます — 加算で足していた頃は背景に紛れて分かりませんでしたが、
下に敷くと暈が背景を隠すので段が目に出ます。

発光層は**アトラスと同じ解像度では持ちません**。1/3 に縮めてから抜き出すので
1 キャラ 16MB 程度で済み、ページを 8Mpx で割っている意味（iOS のデコード上限）も
保てます。重ねるのはぼやけた光なので、縮んでいてむしろ都合がよく、縮めてから
抜き出しても取りこぼしは 95〜107%（実測）でほとんどありません。等倍で判定すると
読み出しが 7 倍になるので割に合いません。焼くのに掛かるのは 120ms 程度なので
**読み込みが済んだ時点で先に焼いて**います（最初に描くときに焼くと、ラウンドの頭で
1 フレーム落ちます）。

**光の弧（`spawns` の `slash`）はこの穴埋めには使っていません。** 以前は振りに重ねて
水色の弧を出していましたが、白い芯の入った帯が振るたび前へ出るので、
**刃ではなく帯のほうが攻撃の絵に見えてしまいます**。いま弧が残っているのは
「絵の刃より判定が先まで出ている技」だけ（串刺しの突きと錐揉みの回転）で、
一番よく振る切り抜けには付けていません。判定を持たない技（後退ブースト・宙返り降下）にも
付けません。光の弧は「ここに攻撃判定がある」という合図でもあるので、当たらない技に
付けると嘘になります。`npm test` がこの対応も見ています。

錐揉み突進が完全な水平ではなく、27 フレームで 81 だけ沈むのは**当てるため**です。
attack2 シートは体を地面と平行にした姿勢で、絵が足元原点から 43〜223 に描かれています
（＝胸の高さに浮いている）。高度を保ったまま飛ぶと立っている相手（高さ 198）の頭上を
素通りするので、突進の途中で相手の高さへ降りてくるようにしてあります。
進む 248 に対して沈むのは 81 なので、見た目は水平のままです。

#### 忍者（置くもの・消えるもの・動かせるもの）

他の 7 人は「振った技が当たるか」で勝負が決まります。忍者だけが
**技を出す時点と当たる時点が離れている**キャラで、置いたまきびしと、
消えている間に取り直した位置が仕事をします。

そのぶん振り合いそのものは全キャラで一番弱く、回し斬りの実効射程は 239
（剣士 273 / キャヴァリア 302）しかありません。**ガードを崩す手段を持たない**のも
このキャラだけです（スキルが煙玉なので）。固めてくる相手には、まきびしで
下がれなくしてから振るか、竜巻で上から潰すかしかありません。

**回し斬り**（攻撃）は「踏み込み（`twirl`）→ 回し（`twirlSpin`）」の 2 つに分けてあります。
attack_twirl のシートは初めからランジで踏ん張っている絵なので、それだけを出すと
「その場で湧いた構えのまま滑って前に出る」ように見えます。前に体重を乗せる 1 歩を
挟むと、そのあとのランジが**踏み込んだ結果の姿勢**として繋がります。

- 踏み込みの絵は専用シートではなく、**run シートの 4 コマ（1〜4）だけ**を借りています
  （蹴り出す → 膝を上げる → 踏み足が着く）。走りの頭と後半は次の歩へ戻る絵なので使いません
- 前へ入る 39.6 は**判定が出るより前に済ませます**。前進と斬りを重ねると、
  相手からは「間合いの外から急に届いた」ようにしか見えません
- 発生は 9 + 3 で **12**。踏み込みぶんだけ割り込まれる幅は広がっています
- 2 段目は `turnOnStart: false`。踏み込みの 9 ティックの間にすれ違われたとき、
  前に出たのと逆を向いて振り始めないようにするためです

**まきびし**（空中攻撃）は飛び道具の枠（`PROJECTILES.caltrop`）ですが、飛びません。

- **投げるモーションを持ちません。** 絵は落下（`fall`）そのままで、再生速度も
  跳んでいるときと同じです。出しても見た目には何も起きず、こぼれた粒だけが落ちていきます。
  振りかぶる絵を付けると「撒いた」ことが相手に伝わって場所を覚えられます。
  **置いた場所を相手が知らないことがこの技の値打ち**なので、
  モーションを持たないほうが技として強くなります
- 2 ティックおきに 1 つずつ落とします。同時に出すと、開いた手からまとめて
  放したように見えて「投げた」に戻ってしまいます
- 落ちたところで止まって居座ります
  （`restOnGround`。落下は `gravity` だけで作っていて、初速は 0）
- **寿命は着地から数えます**（`restTicks` ＝ 5 秒）。落ちるのに掛かる時間は
  撒いた高さで変わるので、撒いた瞬間から数えると「置いた罠が何秒もつか」が
  高さで変わってしまいます
- 判定は**低く平たい**（52×34）ので、**歩けば踏むが跳べば越えられます**。
  やられ判定は足元 y=0 から始まるので、浮いてさえいれば上を通せます
- 打撃扱いなので**ガードは通ります**。スキルではないので当然です
- 場に 3 つまで（＝1 回ぶん）。跳ぶたびに重ねて地面を埋めることはできません
- 消える手前で明滅します。切れる時刻が分からないと、撒く側も踏む側も読めません

**煙玉**（スキル）は、**このゲームで唯一、攻撃判定をひとつも持たないスキル**です。
投げ下ろした瞬間から 3 秒間（`vanish`）、

- **完全に透明になります**（キャラ定義の `vanishAlpha` ＝ 0）。**影も消します**
  （renderer が影の濃さに同じ値を掛けているので、姿と一緒に消えます）
- **攻撃とスキルが出せません**（`Fighter.vanishTicks` が入力を弾く）。
  歩き・走り・ジャンプ・ガード・しゃがみは効きます
- **相手の攻撃は普通に当たります。** 透明なだけで無敵ではありません

つまり 3 秒間、自分から手を出せない代わりに位置を取り直せる技です。
半透明にして輪郭を残すこともできますが、そうすると「消えた」ではなく
「薄くなった」になり、相手からは結局どこに居るか見えたままなので、
位置を取り直すというこの技の目的が成立しません。
操作している側は、カメラが自分を追い続けることと、消える直前の位置と
入力から自分の居場所を把握します。

**CPU も見失います。** シミュレーションの中身は全部読めてしまうので、そのままだと
CPU だけが透明な相手を追い続け、煙玉が「自分の攻撃を 3 秒封じるだけの技」に
なってしまいます。`ai.js` は姿が見えている間だけ相手の位置を覚え、消えている間は
**最後に見た位置**へ向かって動きます（隙を突く判断もその間は止まります）。

**竜巻**（空中スキル）は、**プレイヤーが出したあとに行き先を選べる唯一の技**です。

- 空中で止まり、**1 秒かけて回転を上げます**（`tornado` → `tornadoWind` → `tornadoRise`）。
  この 1 秒は判定をひとつも持ちません。魔法使いの照射の溜めと同じで、
  「これから来る」と見せるための時間です。そのぶん空中で 1 秒まったくの無防備になります
- 最高速（`tornadoRide`）からの 2 秒間は、技データの `steer` が**移動操作をそのまま
  行き先にします**。左右で横へ、上下で高さを変えられて、何も入れなければその高さに留まります
- 判定は体の**両側**に出ます（attack_spin シートは体ごと 1 回転する絵で、
  刃が前にも後ろにも届く）。スキルなのでガードごと崩し、刻み 11 発＋締め 1 発。
  ダウンを奪うのは締めだけです（刻みでダウンさせると無敵になって残りが素通りします）
- 立ち上がりと合わせて**3 秒間まったく引き返せません**。その間ガードもできないので、
  読まれて置かれると一方的に落とされます

回転が速くなっていくのは技を 3 段に分けて `animFps` を上げているからです
（絵の速さは技データからしか変えられないため）。渦の絵は `sim.effects` ではなく
**技データの `vfx` を renderer が直接読んで**描いています。寿命を持つ演出にすると、
着地で技が打ち切られたときに渦だけが残ってしまうためです。

**最高速では本人が渦に飲み込まれて見えなくなります。**
ただし飲み込むのは回り切ってからで、立ち上がりの 1 秒は姿が見えています
（`_drawTornado` の `hide`。power 0.55 未満で 0、そこから 1.6 乗で立ち上がる）。
この 1 秒は判定をひとつも持たない無防備な時間で、「これから来る」と
相手に見せるためにあるので、ここで姿まで隠すと、相手からは何をしているのか
分からないまま当たらない技になり、見せるための 1 秒が意味を失います。

覆いは**漏斗の形をした濃い紫の層 3 枚 ＋ にじんだ塊 24 個**で作っています。
層だけで濃さを稼ぐと同じ形の輪郭が並んで等高線に見え（層ごとに輪郭の
揺れ方も変えています）、塊だけにすると漏斗の輪郭まで溶けて湯気になります。
**形は層が持ち、境目は塊が壊す**という分担です。
塗り潰しきらないのは、10 割にすると渦ではなく板が貼ってあるように見えるためです。

色は**気象の竜巻（灰色の土埃）ではなく魔力の渦**として置いてあります
（`TORNADO`）。忍者のテーマ色 #9d7bd8 を基準に、

- **もや／覆い** ＝ 濃い紫。暗く沈める役で、**体を隠すのはここだけ**です
- **帯／筋** ＝ 明るい藤色。加算合成で光らせる、渦の模様そのもの
- **粒** ＝ ほぼ白の藤色。いちばん明るい点
- **影** ＝ 地の色より暗い紫。明るい線ばかりだと紙吹雪に見えます

と役割ごとに明るさを離してあります。**段が近いと、重ねても模様が出ません。**
光らせるのは帯と粒だけです。**加算合成は下を明るくするだけで何も隠せない**ので、
覆いまで光らせると「明るいのに向こうが透けて見える」ことになります。

渦そのもの（`Renderer._drawTornado`）で効かせているのは次の点です。
輪を積むだけの描き方をすると、渦ではなく輪投げに見えます。

| | やっていること | これが無いと |
|---|---|---|
| 芯を蛇行させる | 高さごとに中心を横へずらし、周期の違う波 2 本で揺らす | まっすぐな円錐＝置物に見える |
| 輪ではなく帯を巻く | 高さと角度が同時に進む螺旋（太い帯 11 本＋細い筋 40〜60 本） | 輪が縦に積まれて「輪投げ」に見える |
| **太い帯は面で描く** | 中心線の左右へ振った多角形を塗る | 線分ごとの丸い端が並んで**数珠**に見える（分割を細かくするほどひどくなる） |
| 濃くしたら帯も濃くする | 手前の覆いと一緒に筋の濃さ・太さ・本数を上げる | 最高速で筋が覆いに埋もれ、紫の塊になる |
| 帯を下から上へ流す | 各帯の開始高さを時間で送る | 回ってはいるが吸い上げていない |
| 縁を毛羽立たせる | 左右で違う揺れ方をさせ、層ごとに位相も変える | 輪郭が平行に並んで等高線に見える |
| 明暗を混ぜる | 3 本に 1 本を地の色より暗く引く（暗い帯だけ加算にしない） | 光った線の集合＝紙吹雪に見える |
| 腹をいちばん濃くする | 足元と上端の濃さを落とす | 細い先端で層が重なって懐中電灯に見える |
| **塗りを t=1 より上まで伸ばす** | 形は 1.35 まで、濃さは 1.06〜1.1 で 0 にする | 左右の輪郭が閉じる線が渦の頭を横切って見える |
| 縁を 1 本なぞる | 左右を別々に、上端は閉じずに引く | もやの塊のままで、形のあるものに見えない |
| 粒を線で描く | 進行方向へ伸ばした短い線にする | 粒だけ止まって見え、渦から浮く |
| 地面が近いと風が散る | 足元の高さ（110 未満）で濃さを決める | 地面すれすれでも空中と同じ絵になる |

上端の直径（220 前後）は**判定の横幅 240 に合わせて**あります。
ここを広げると、見えている渦の外側が当たらない範囲になって嘘になります。

#### 戦闘メイド（縦に長い刃と、引き返せない放物線）

横の間合いはこのゲームで下から 2 番目です。横薙ぎの実効射程は 238 で、
剣士（273）にもキャヴァリア（302）にも届かず、歩きも 2.8 と魔法使いに次いで
遅い。**入られる前に押し返す**ができないキャラです。

代わりに**どの技も判定が縦に長く**なっています。

| 技 | 判定の高さ | 意味 |
|---|---|---|
| 横薙ぎ | 44〜194 | しゃがみ（0〜100）の上から立ちの頭まで |
| 叩き割り | 26〜208 | **地面から頭上まで**。跳んでもしゃがんでも同じ刃が通る |
| 天空斬り・上り | 58〜252 | 自分の身長より上。跳んで逃げた相手を迎えにいく |
| 天空斬り・落とし | -16〜172 | **足より下**。落ちてくる技なので足元を踏み抜く |
| 回転斬り | 4〜206（前後とも） | 体ごと回るので、前にも後ろにも |

つまりこのキャラを相手にすると「避ける」ではなく
「ガードするか、割り込むか」を選ぶことになります。

**天空斬り**（スキル）は `aether_rise`（上り）と `aether_slam`（落とし）の 2 つに
分けてあります。入力は最初の 1 回だけで、上りを出し切ると必ず落としへ繋がります（`onEnd`）。

- 踏み切りは **vy 21 の一発**だけを技データに書いてあります。区間で vy を書き続けると
  重力が効かず等速で昇ってしまうので、初速だけ与えて残りは重力に任せます。
  出し切る 34 ティック目には、およそ 300 ＝ 身長の 1.5 倍まで昇っています
- **上りはダウンを奪いません。** ダウンさせると相手はその時点で無敵になり、
  せっかく打ち上げた相手を落としが素通りしてしまいます。打ち上げるだけにして、
  落ちてくるところへ落としを重ねる形にしてあります（近い間合いなら 2 HITS）
- 落としは vy を毎ティック -15 で上書きするので、重力に関係なく一定の速さで落ちます。
  空中で出した技は着地で打ち切られるので、**この技は必ず地面で終わります**
- 出してから着地するまでおよそ 57 ティック。**その間ずっと引き返せません。**
  落ちる先は跳んだ時点で決まっているので、相手は下からどけばよく、
  外せば着地硬直 24 がまるごと残ります

**空中スキルは落とし（`aether_slam`）そのもの**です。上りから繋がってきたぶんと、
跳んでいる最中にスキルを押したぶんが、同じ技・同じ判定になります。

**回転斬り**（空中攻撃）の絵は体ごと 1 回転する 8 コマの閉じたループなので、
`animLoop` で回し続けます（24fps ＝ 1 周 20 ティックで、技の間に 2 周）。
刃が前を通るたびに 1 回、計 2 発当たります。刻みにダウンを付けていないのは、
ダウンさせるとその時点で相手が無敵になり、2 発目が素通りするためです。

**落としの着地**（`landImpact`）だけは、着地の扱いを他の空中技と変えています。
ふつうの空中技は地面に着いた瞬間 land（立ち上がり）の絵へ移りますが、この技の
シートは**低く沈んで包丁を地面へ叩き込んだ最後のコマ**が見せ場なので、
そこで切り替えると一瞬も出ないまま終わります。そこで着地したら

- その技の**最後のコマを硬直 24 ティックのあいだ保持**し（刃は地面に刺さったまま）
- 足元に**土煙**（`dust`）を出し
- 画面を **18 揺らします**（叩きつけダウンの 10 より強い、全キャラで一番大きい揺れ）

砂埃は煙玉の煙とは別の描き方をしています（`_drawDust`）。あちらは体を隠すための
丸い塊で、その場に湧いて留まりますが、こちらは踏み抜かれた地面から**舞い上がる砂**です。
3 つを重ねて作っています。

| 層 | 何をしているか | 無いとどう見えるか |
|---|---|---|
| **裾** | 足元から左右へ一気に逃げる、低くて薄い空気。寿命の 1/3 で消える | 着いた最初の 2〜3 コマに何も出ず、「ドン」と来ない |
| **塊**（20 個） | 横へ逃げてから**上へ巻き上がる**。昇るほど膨らみ、潰れた楕円から丸へ崩れる | 這ったまま消えて、砂埃ではなく地を這う霧になる |
| **砂粒**（38 個） | 斜め上へ弾かれて放物線で落ちる。3 粒に 1 粒だけ速い | 塊だけだと湯気に見える。逆に粒だけだと火花になる |

数字で効いているのは **横より縦を大きく取ること**（横は最大 0.7・縦は 1.2）と、
**消え際を 1.7 乗で引くこと**の 2 つです。横に広げると靄が画面に残って霧になり、
真っ直ぐ薄くすると最後まで灰色の膜が残ります。
色は白ではなく月明かりを受けた砂にしてあります（白いと煙玉と見分けが付きません）。

砂粒の位置は**経過時間から毎回計算し直します**（弾道式）。粒ごとの状態を持たないので、
巻き戻しても描画を飛ばしても、同じ `seed` と経過時間なら必ず同じ絵になります。

**ジャンプの絵**は `animRanges` で前半を捨てて `[3, 7]` だけ使います。
jump シートは 8 コマのうち前半 3 コマが屈み込みと踏み切りですが、ゲーム側では
ボタンを押した瞬間にもう初速が乗っていて、上がり切るまで 24 ティックしかありません。
頭から 11fps で流すと、**昇っている間ずっと「地面で屈んでいる絵」のまま頂点に着き**、
空中の姿が 1 コマも出ませんでした。

このキャラは**アトラスを焼くときにアンカーを 3 か所直しています**。
どれも「絵の中で本人が居る場所」と「足元アンカー」がずれている行で、
直さないと**やられ判定が本人から外れます**（＝刃のあたりを殴られると当たり、
体を殴られてもすり抜ける）。

| 対象 | ずれ | 直し方 |
|---|---|---|
| `maid4` シート全体 | 待機で包丁を体の後ろへ低く提げていて、**切っ先が靴と同じ高さ**まで下りる。足の帯を見る `foot` の中に刃が入り、原点が体より 45 後ろに寄る | `dx = 103`（px。ワールド 45 ぶん前へ） |
| `spin_slash` | 体ごと回る絵なので、**回転の中心（腰の高さ）**がアンカーに乗っている。そのままだと体が 70 浮く | `nudge` で下へ 70 |
| `aether_slam` | クリップの中でキャラが左に寄ったまま撮れていて、落ちてくる本人だけが後ろに描かれる | `nudge` で前へ 45 |

描画側ではなくアンカー側で直しているのは、**左を向いたときの反転が勝手に正しくなる**ことと、
選択画面やデバッグ表示まで含めて全部の描き手が同じ位置を見るからです
（1 行目を直すと、選択画面のサムネイルで体が右に寄るのも一緒に直ります）。

#### 巫女（スキルにだけ勝つ結界）

このゲームのスキルは全部「ガードの上から通る」ことで成立しています。固められた側は
スキルで割り、割られた側はさらにスキルで割り返す。**結界はそこだけを咎めます。**

| 当たったもの | 結界の答え |
|---|---|
| スキル（`guardBreak` を持つ技） | **無効化して返す** |
| 掴み（`grab`。淫魔の吸血・キャヴァリアの串刺し） | **無効化して返す** |
| スキルの飛び道具（女子高生の彼氏） | **無効化して、その弾も砕く** |
| 打撃 | **素通し**（普通に食らって死ぬ） |
| 普通の飛び道具（ホーミング弾・レーザー） | **素通し** |

避ける技ではありません。**スキルを読んだときだけ通る返し**です。

- 張るまで **14 ティック**、張っていられるのが **40 ティック**、技が終わるまで **64 ティック**
- 発生 14 は「振られたのを見てから合わせる」には遅く、**振ってくると読んで先に張る**技です
- 読み負けたら、1 秒強の棒立ちがまるごと相手の取り分になります

弾いた瞬間は両者の時間が **13 ティック**止まり（`WARD_REPEL_HITSTOP`）、明けたところで
返し技（**結界破**）が出ます。欠片は**自分の体の中心**から相手を狙って 3 つ、
散り札と同じ扇に開いて飛びます。弾かれた相手はたいてい大技を振り切ったところなので、
ガードも回避も間に合いません。

**返しに移るのは 1 回だけです。** 結界そのものは残り時間ぶん張られたままなので、
魔法使いの照射のように**何度も当たるスキル**は、2 発目から「弾くだけ」になります。
当たるたびに返し技を出し直すと、モーションが頭へ戻って何も返せないまま
照射が終わってしまうためです（結界を張ったまま照射をまるごと受け切って、
明けてから欠片を返す形になります）。

結界の状態は技ではなく**ファイター側のティック**（`wardTicks`）で持っています。
技と一緒に持つと、返し技へ移った瞬間に結界が消えてしまうためです。
別の技を出せば解けるので、張ったまま殴りに行くことはできません。

**当てる手段は御札だけです。** 打撃判定をひとつも持たないのは女子高生と同じですが、
あちらには「呼べば勝手に詰めてくれる彼氏」がありました。こちらにそれは無く、
詰められたら結界を張るか、跳んで間合いを外すかの二択になります。

- **御札**（地上）は投げ切った指先（前方 134 / 高さ 163、`attack` シート f4 の実測）から
  まっすぐ横へ飛びます。**胸の高さを飛ぶので、しゃがまれると下を通ります**
  （女子高生のレーザーと同じ弱点で、理由も同じ「絵の手元の高さ」です）
- **散り札**（空中）は**その瞬間の相手を狙って** 3 枚。真ん中の 1 枚が一直線に、
  残り 2 枚がその左右へ **16 度**開きます。狙った線から少しずれた位置に逃げても
  引っかかり、逆に 3 枚の間を抜けるように動かれると 1 枚も当たりません
- **踏み降り**（空中スキル）に**攻撃判定はありません**。跳んだあとの
  「降りるまでの時間」を自分で縮めるための技で、対空を透かして地上の読み合いへ
  戻るために使います。着地硬直 16 があるので、降りる場所は選ぶ必要があります

扇の開き（±16 度）は cos / sin を**定数として技データに書いてあります**。
`Math.cos` / `Math.sin` は実装ごとに最下位ビットがずれうるので、
同じ入力から必ず同じ試合になることを守りたいシミュレーションの中では使いません
（追尾弾が三角関数を使っていないのと同じ理由です）。

**空中で投げる行（`airattack`）だけはアンカーを直しています。** 跳んだ姿勢のまま
撮った行なので、他の 13 行より足が 53 ワールド単位ぶん高いところに描かれていて、
そのままだと投げた瞬間に本人だけがふわりと浮き上がります
（`build-assets.ps1` の `nudge` で下へ 53。戦闘メイドの `spin_slash` と同じ直し方です）。

結界の見た目（`_drawWard`）で効いているのは次の 4 つです。

| | やっていること | これが無いと |
|---|---|---|
| **球として描く** | 体を包む円を 1 つ。前だけの壁にしない | ガードの光壁と見分けが付かない |
| **御札を回す** | 8 枚を円周に立てて、ゆっくり回す | ただの光の輪＝何の技か伝わらない |
| **消える手前で薄れる** | 残り 14 ティックから薄くする | 切れた瞬間が分からず、相手が振り得になる |
| **位相を残りティックから作る** | `wardTicks` を回転角に使う | リプレイのたびに違う絵になる |

張った瞬間（`wardUp`）と割れた瞬間（`wardBreak`）は同じ関数で描いています。
どちらも同じ球の出来事なので、別々に描くと張ったときと割れたときで
結界の大きさが食い違って見えます。張るときは外から輪が締まり、
割れるときは輪が外へ弾けて破片が散ります。

CPU も結界を見ています。**結界を張っている相手にスキルは振りません**
（`ai.js` の `skillUsable`）。振った時点で無効化されて欠片が返ってくるので、
崩しは打撃に任せます。

#### 格闘娘（全部キャンセルできるコンボ屋）

このキャラだけ**技の並びが決まっていません。** 他のキャラの連携は「この技の
この窓でだけ次へ繋がる」ものですが、格闘娘は**どの技も、判定の次のフレームから
技の最後まで、ずっと次の技を受け付けます**。

|  | 攻撃ボタン | スキルボタン |
|---|---|---|
| 刻み突き（1 打目） | → 打ち抜き | → サマーソルト |
| 打ち抜き（2 打目） | → 刻み突き | → サマーソルト |
| 刻み突き（3 打目） | → **波動突き** | → サマーソルト |
| 波動突き（4 打目） | → 刻み突き（1 打目へ戻る） | → サマーソルト |
| サマーソルト（空中） | → 飛び蹴り | → 回転かかと落とし |
| 回転（弧を描いて跳ぶ前半） | → 飛び蹴り | → **飛び足刀** |
| 飛び蹴り | — | → 回転かかと落とし |
| 飛び足刀 | — | — |

つまり **地上の連打 → サマーソルトで浮かせる → 自分も追って空中の連携** が
1 本に繋がります。

空中も、回転と飛び蹴りの間は**互いにキャンセルできます**（蹴りが空を切ったのを
見てから弧で跳び込み直す、という往復ができます）。往復しても浮き続けられないのは、
**飛び蹴りが重力に任せる技**だからです。蹴っている間はそのぶん落ちますし、
弧のほうも降り切って 20 下がるので、回るたびに高度は減っていきます。

そのうえで、**空中で繋げるのは 3 回まで**です（`airChainLimit`）。地上は押し出しが
歯止めになりますが、空中にはそれが無いので回数のほうで区切っています。
数えるのはボタンを押した繋ぎだけで、回転からかかと落としへの `onEnd` は数えません。
**数え直すのは着地したときだけ**なので、跳び直さないと戻りません。

| 跳んでからの一例 | |
|---|---|
| 跳ぶ → 飛び蹴り → **①**回転 → **②**飛び足刀 | 足刀で打ち止め |
| 跳ぶ → 回転 → **①**飛び蹴り → **②**回転 → **③**飛び蹴り | 3 回で打ち切り |

ただし**飛び足刀（2 段目）へ抜けたらそこで打ち止め**で、回転へは戻れません。
足刀は高さを保ったまま真横へ抜ける技なので、戻れるようにすると
落ちてこないまま択を掛け続けられてしまいます。

##### 4 打目に波動弾

突きを続けると **4 の倍数の打**で波動弾（`kiBlast`）が飛びます。
**このキャラで唯一の飛び道具**ですが、他のキャラの弾と違って**単体では撃てません**。

- 出すには 刻み突き → 打ち抜き → 刻み突き を**振り切る**必要があります。
  途中で手を止めれば 1 打目からの数え直しです
- 場に出せるのは **1 発**。当たるか消えるまで、4 打目を回しても次は出ません
- 弾は**肩の高さ（148）をまっすぐ**飛ぶので、**しゃがまれると下を通ります**
  （巫女の御札・女子高生のレーザーと同じ弱点で、理由も同じ「拳の高さ」）

つまり波動弾は**間合いを取り直す手段にはなりません**。撒いて近づけなくする
使い方ができないので、リーチの短さを自分の足で埋める、という性格は変わらないままです。

4 打目（`punch4`）だけ絵の再生が 22fps とひと呼吸ぶん遅く、発生も 10 と 2 遅くしてあります。
撃つ打だと分かる溜めを作るためで、弾が拳を離れるのは腕を伸ばし切る 11 フレーム目。
**近ければ拳が、遠ければ弾が当たります。**

1 打目と 3 打目は**まったく同じ技**（`punch1` / `punch3`）です。分けてあるのは
打数を数えるためだけで、`chains` は技から技への辺しか持てず、回数を数える仕組みが
無いためです。

**代わりにリーチが全キャラで最も短くなっています。**

| | 実効射程 | 発生 |
|---|---|---|
| **格闘娘（刻み突き）** | **144** | **6** |
| 淫魔（引っ掻き） | 164 | 7 |
| 忍者（回し斬り） | 239 | 12 |
| 剣士（横切り） | 273 | 16 |
| キャヴァリア（切り抜け） | 315 | 8 |

踏み込みも飛び道具も持たないので、**届く間合いは自分の足で作るしかありません**。
そのぶん発生 6 は全キャラ最速で、間合いさえ作れば先に手が出ます。

##### 地上で届かないぶん、縦と横に伸びる

| 技 | 移動 | 1 回で動く距離 |
|---|---|---|
| **サマーソルト**（スキル） | 初速 16 で真上へ | 頂点 **234** ＝ ジャンプ（202）より高い |
| **飛び蹴り**（空中攻撃） | **移動指定なし**（跳んだ弧のまま） | 跳び方しだい |
| **回転**（空中スキル前半） | 敵の方へ弧を描いて跳ぶ | **168**（頂点で 72 上がり、終わりは 20 下） |
| **飛び足刀**（空中スキル 2 段目） | 前へ 11・落下を 0 に固定 | **220**（高さを保ったまま） |

**空中攻撃だけは軌道を持ちません。** `motion` を持たないので縦にも横にも触らず、
出した瞬間の速度がそのまま残ります。**上りで出せばそのまま上がり続け**、
前ジャンプなら前へ流れたまま、降り際に出せばその場で落ちながら蹴ります
（＝**跳び方がそのまま蹴る位置**になります）。空中で自分から軌道を作る役は
回転の弧と飛び足刀が持っています。地上の間合いでは何も届かないキャラなので、
**跳んでからの移動が距離を作る手段**であることは変わりません。

絵は 8 コマを **26fps ＝ 18 ティックで流し切って、足を伸ばした最後のコマで残りを持たせます**
（全体は 30）。jumpkick シートは f3 から先がずっと足の伸びた絵なので、速く流すほど
「伸ばして置いている」時間が長くなります。判定もその絵に合わせた **8〜18**（f3〜f7）で、
発生 8 は剣士の飛び斬り（7）・狂戦士の空中乱舞（8）と同じ並びです。
サマーソルトも跳ぶ技ではなく蹴り上げがそのまま上昇になる技なので、
ジャンプより上へ行きます。代償は空中にいる時間そのもの（全体 58 ＝ 1 秒近く）で、
出したら引き返せませんし、ガードもできません。

##### 浮かせるのにダウンを使わない

このゲームのコンボは**ダメージのためではなくヒット数のため**にあります
（当たった時点で体力は 0 になり、のけぞりが解けたところで崩れ落ちる）。
だからサマーソルトには `knockdown` を付けず、`launch` だけを持たせています。
ダウンさせるとその瞬間から相手が無敵になり、せっかく浮かせた相手に
空中技が一発も入らなくなるためです。

締めの**かかと落としだけが `knockdown` を持ちます**。打ち上げ量を 2 まで落として
あるので、浮くというより地面へ叩きつけられて、そこでコンボが終わります。

##### 固めが無限にならない理由

刻み突きは発生 6・ガード硬直 9 で、次の技へ繋げるのは 7 フレーム目です。
数字の上ではガードを固め続けられますが、**1 発ガードさせるたびに相手は
押し出されます**（`pushBlock` 2.4〜3.0）。リーチが短いので、3〜4 発も固めれば
自分から間合いの外へ追い出すことになります。

逆に**当てたときの押し出しは 0.9〜1.4 しかありません**。繋ぎ先（サマーソルトの
前方 92）が突きより短いので、当てるたびに押していると自分のコンボが自分で
届かなくなるためです。**通っている間だけ近く、止められている間は離れていく**、
という差をこの 2 つの数字で作っています。

##### 回転かかと落としは「弧で運んで真下へ踏み抜く」

空中スキルは 2 つの技に分かれています。

1. **回転**（`heelSpin`）… 丸まったまま**相手の方へ弧を描いて跳ぶ**。
   32 ティックで前方 168 を運ばれ、頂点で 72 上がって、終わりは出した高さより 20 下。
   絵は `flipheel` シートの回転コマ 3 枚を**ループ**させています
2. **かかと落とし**（`heelDrop`）… 弧を降り切ると `onEnd` で必ず繋がる技。
   横の勢いを切って、頭上まで上がった足を**真下へ**振り下ろします

**回転そのものには攻撃判定がありません。** 当たるのは踏み抜く後半だけです。
判定を持たない代わりに**弧の分だけ確実に間合いを詰められる**技になっていて、
空中攻撃（飛び蹴り）が跳んだ弧をなぞるだけの技なのと対になっていて、
**空中で自分から間合いを作るのはこの弧だけ**、という役割分担です。

弧の上下は重力ではなく `motion` の vy を 4 区間で落として作っています
（+7.0 → +2.0 → -3.5 → -8.0）。重力に任せると跳んだときの勢いが混ざって、
**出した高さごとに弧の形が変わってしまう**ためです。横も 6.5 から 3.5 へ落として、
終わり際で失速してそのまま真下へ落ちる形にしてあります。

踏み抜きの判定は 4〜22 と長く、落下 -13 を掛けて **247 ぶんの高さを踏み抜きながら
降ります**。弧の終点さえ相手の頭上に乗っていれば、そこから地面までのどこかで当たります。

##### 立ち姿のまま落とさない

`flipheel` の振り下ろしは**立ったまま足を真上へ上げた**コマ（腰から見て 79 度上）
なので、そのまま落とすと「立ち姿が地面へ降りてくる」画になります。技データの `tilt` で
**絵だけを 50 度寝かせて**、上げた足が斜め前（29 度）まで下りた姿勢にしてあります
（回っている勢いのまま足を放り出した形）。水平まで寝かせると横倒しに見えるので、
**体は斜めに残して**あります。

傾きは**技の間ずっと 50 度で固定**です。振り下ろしながら体を起こすと、
絵のコマが変わらない 4.6 ティックの間だけ足が逆向きに上がって、コマが変わった瞬間に
落ちる**ガクつき**になります。足を振り下ろす動きは絵のコマ（f4 → f7）が
もう持っているので、傾きのほうは動かしません。

傾けるのは絵だけで判定は動きませんが、**見た目に合わせて判定のほうを寝かせて**
あります（前方 6〜116・高さ -8〜132）。前端 116 は飛び足刀の 134 を超えない
ところで止めてあり、一番遠くへ届くのは横へ抜ける足刀、という並びは崩していません。

**外したときの着地硬直は 14** ＝ 通常（7）の倍です。回転に判定が無い＝
**弧を出した時点で踏み抜く場所を決めている**技なので、読まれて動かれたぶんが隙になります。

着地は `landImpact`（{shake: 10, dust: 26, radius: 110}）で、**足元に土煙を上げて
画面を揺らします**。絵は `hold` を立てていないので**ジャンプと同じ着地（land）**へ移ります。
踏み抜いてそのまま立て直す蹴りなので、天空斬りのような「刃を突き立てて固まる」
決めの絵を持たないためです。**後隙は変わりません**。硬直の長さを決めているのは
`landLag`（14）のほうで、`landImpact` は「その間に何を見せるか」だけの指定です。
揺れ 10 は叩きつけダウンと同じで、天空斬りの 18 より小さくしてあります
（落としているのが刃物ではなく踵ひとつなので）。

回っている最中に**もう一度スキル**を入れると **飛び足刀**（`flyKick`）へ移り、
落下を打ち消して真横へ 11（このキャラで一番速い移動）で飛びます。そのまま出し切って
**上から踏み抜く**か、**水平に蹴り抜く**かを弧の途中で選べるので、跳び込むと
見せてから横へ抜ける択が作れます。往復もできますが、回転は弧を降り切って 20 下がり、
足刀も後半は自然落下に戻るので**高度は往復のたびに下がります**
（空中に留まり続けることはできません）。

##### 空中で撮った 2 行だけアンカーを下げている

`jumpkick` と `flykick` は空中で撮った行で、他の行より体が高い位置に描かれています
（飛び蹴りは後ろ脚を体の下へたたむので足元が 88、飛び足刀は蹴りのコマを
持ち上げてあるので 31 ぶん浮く）。そのままだと跳んで攻撃した瞬間に本人だけが
さらに浮き上がり、**伸ばした足がやられ判定よりずっと上に描かれます**。
`build-assets.ps1` の `nudge` で立ち姿と同じ胴体の位置まで下げてあります
（巫女の `airattack2` と同じ直し方）。

`jump` / `fall` / `land` を直していないのは、あの 3 行が**跳躍の弧そのもの**を
撮った行だからです（持ち上がりは絵の一部で、全キャラ同じ扱いにしてあります）。
`flipheel` / `somersault` も直していません。回転のコマは浮きますが、
**判定を持つコマ**（かかと落としの振り下ろし・蹴り上げ）はどちらも
接地の高さに描かれているためです。

### 画面まわり（`index.html` / `styles.css`）

画面は `index.html` の `<section class="screen">` を出し入れするだけで、
どれを出すかは `src/ui/screens.js` の `ScreenManager` が持っています。

**タイトルには細かい説明を置いていません。** ルールと操作は
「遊び方」（`#screen-howto`）に分けてあり、タブで
ルール / 操作方法を切り替えます。タイトルはロゴとモード選択だけです。

**キャラクター選択でスクロールするのはキャラの並びだけ**です
（`.roster-scroll`）。見出し・技の説明・決定ボタンは
スクロールの外（`.panel-flex` の固定行）に置いてあるので、
どこまで並びを送っても「決定」が画面から消えません。

見た目は「格闘ゲームの筐体」に寄せてあり、面はすべて角丸ではなく
**斜めに切り落とした形**（`--cut-panel` / `--cut-btn` / `--cut-card`）です。
`clip-path` で切ると `border` が斜辺に付いてこないので、縁取りは
「親の背景を 2px だけ覗かせる」で作っています
（`::before` を `z-index: -1` で内側へ落とし、親は `isolation: isolate`）。

なお `body` の `touch-action` は `none` ではなく `manipulation` です。
`none` にすると**子でスクロールを許可し直せない**ため、キャラ選択が
スマホで動かなくなります。試合中の指は必ず `.zone` か `#stage` の上にあり、
どちらも `touch-action: none` なので、実害のあるスクロール・ピンチは
そちらで止めています。

### 血しぶきの作り方（`renderer.js`）

決着の演出なので、ここだけは作り込んであります。安っぽく見えないために効いているのは
主に次の 4 つで、いずれも `_drawBlood` / `_bloodParticles` の中にあります。

| | やっていること | これが無いと |
|---|---|---|
| **粒径をべき分布に** | `0.32 + u^4.6 * 3.1`。ほとんどが微細な粒で、大粒はごく少数 | 同じ大きさの丸が並んで、一気に嘘くさくなる |
| **空気抵抗** | `dv/dt = -k・v - g` の解析解で飛ばす。`k` は粒径に反比例 | 全部が同じ形の放物線を描く。抵抗があると小粒はその場に落ち、大粒だけが遠くまで届く |
| **着地したら床の染みに** | 着地時刻を粒ごとに先に解いておき、以降は染みとして描く | 落ちた血が消えてしまう |
| **加算合成を使わない** | `source-over` の暗い静脈血。薄く伸びた部分だけ少し明るく | 血が光る。光った瞬間に嘘になる |

粒ごとの初期値は描画側の `WeakMap` に持っています。エフェクト自体
（＝シミュレーションのデータ）には書き戻さないので、ロールバックしても壊れません。
飛沫が一番多いフレームでも `render()` は約 4.8ms（60fps の予算 16.7ms）です。

### CPU の考え方（`ai.js`）

一発当たったら即死なので、手数を増やすより **振るか振らないかの判断**がほぼ全部を決めます。
そこで CPU は次の 3 つを土台にしています。

| | やっていること | これが無いと |
|---|---|---|
| **技の性能を技データから読む** | 判定リーチ・**前進量**・発生フレームを `profileOf()` で割り出し、届く間合いでしか振らない | 数値を手で持つと技を調整したときに置いていかれる。剣士のタックルは判定リーチ 142 でも 182 前進するので、前進を見ないと「実際は届く間合い」で振らなくなる |
| **相手の隙を数える** | 空振りの戻り・着地硬直・のけぞり・ガード硬直を `_openFrames()` でフレーム数として出し、自分の発生が間に合うときだけ差し込む | 手当たり次第に振って差し返される。突っ込んでくる相手への勝率が実測で 11 ポイント変わりました |
| **ガードは崩す / 崩されない** | 固める相手にはスキル（ガード貫通）、届かない技にはガードを固めない | 固めるだけの相手を崩せない。逆に届かない技へガードを固めると差し込む機会を捨てる |
| **飛んでくる弾を捌く** | `sim.projectiles` を見て、**相対速度**で到達時間を出し、ガードで受ける | 弾は撃った本人と切り離して飛ぶので、技のモーションだけ見ていると気づけない。魔法使いを相手にすると弾に向かって歩いて当たりに行く |

**飛び道具まわりは直感が外れます。** 実測して分かったこと。

- **ただ跳ぶのは逆効果。** 魔法使いの弾は杖の先（足元から 248）から出て
  追尾しながら降りてくるので、跳ぶと弾の高さへ自分から入ります。
  しかも空中はガードできないので、外したらそのまま食らいます。
  **ただし 2段ジャンプなら避けられます**（下記）
- **しゃがみも効きません。** 弾はしゃがんだぶん狙いを下げ直してきます
  （`homeToward()` がやられ判定の中心を狙うため）。効くのは照射ビームだけです
- **弾を持つ相手には跳ばない。** 滞空は自分の身長ぶんで 50 フレーム超あり、
  弾の発生は 11 フレーム。跳んだ時点で弾が無くても、空中で撃たれて終わります。
  実測では、跳んで弾に当たった 36 回のうち 35 回が「跳んだ時点では弾が無かった」ケースでした
- **到達時間は相対速度で見る。** 弾の速さだけで割ると、弾に向かって走っているとき
  倍近く遅く見積もり、気づいたつもりで間に合いません。これが被弾の主因でした

つまり弾への基本の答えはガードです（弾は `guardBreak` を持たないので確実に止まります）。
反応し始める距離も実測で決めました。短いと受け損ない（到達 14 フレームで反応 → 勝率 0%）、
長いと弾を見るたびに固まって近づけません（60 フレーム → 4%）。34 フレームが一番受けられました。

#### 2段ジャンプでホーミング弾を避ける

ガード以外にもう一つ答えがあります。総当たりで探して見つけた型です。

> **真上に跳ぶ → 弾が 145px まで近づいたら「前へ」跳び直す** … 成功率 **7 割**

1段目だけでは 0〜7% しか避けられず、**避けているのは 2段目**です。
弾は `turnRate` が低くて曲がりきれないので、間近で軌道を変えると置いていけます。
2段目が前方向なので、避けながら間合いも詰まります。

2段目の合図に**残りフレームではなく弾との実距離**を使うのが要点でした。
曲がる弾は到達時間の見積りが当てにならず、残りフレームで合わせると成功率は 14% まで落ちます。

跳び始める窓にも上限が要ります（`DODGE_ARM_MAX`）。早く跳びすぎると弾が来る前に
着地してしまい、2段目を弾に合わせられません。

**溜め技の扱いにも注意が要ります。** 魔法使いの照射は溜めの段階では判定を 1 つも持たず、
`onEnd` の先に本体があります。さらに溜めは演出用の魔法陣を `spawns` に出すので、
これを発生フレームと取り違えると「発生 0 の技」だと思い込んで**密着で溜め始めて的になります**。
`isProjectile()` で実弾だけを見るようにしてあります。

**最善手を毎回選ばせてはいけません。** 一度そう作ってみたところ、勝率は上がったのに
遊ぶと弱く感じるようになりました。同じ状況でいつも同じ答えを返すので、
数ラウンドで読まれて対策されるからです。原因は測り方にもありました
（ベンチの相手は学習しないので、読みやすさが罰されない）。

そこで `think()` は状況ごとに**有効な手を重み付きで並べ、そこから選ぶ**形にしています。

- 「相手の技が来ている」なら ガード / 跳んで越える / 下がって空振りにする /
  しゃがんでくぐる / 発生で勝てるなら割り込む
- 「相手に隙がある」なら 打撃で差し込む / スキルで差し込む / 走って詰める / 様子見
- 「間合い争い」なら 振る / 崩す / 歩いて詰める / 走って詰める / 飛び込む / 待つ / 下がる

**逃げる手には時間の裏付けを付けています。** 跳ぶ・下がるは動き出しに時間がかかるので、
判定が出るまでの残りフレーム（`_framesUntilHit()`）が足りているときだけ候補に出します。
ここを見ないと「逃げようとして食らう」が増えて、実測で 5 ポイント落ちました。

さらに **直前と同じ手は重みを落とし**、数秒ごとに切り替わる**気分**
（攻め / 守り / ふつう）で偏りを揺らしています。同じ距離でも局面によって答えが変わるので、
「この間合いならこう来る」と読み切られにくくなります。

難易度は `DIFFICULTY` の 3 段（`easy` / `normal` / `hard`）で、
各手の重みと `hold`（決めた行動を引きずる時間の倍率）を変えています。
弱い設定ほど長く引きずるので、状況の変化に置いていかれます。
CPU 戦もアーケードも `hard` を使っています（`src/main.js` の `new CpuController(1, 'hard')`）。
アーケードで難易度を上げていかないのは、**1 戦目から全力の相手を出したほうが
「10 戦勝ち抜く」の意味がはっきりする**ためです。

### アーケード（勝ち抜き）

タイトルの「アーケード」は CPU との一本勝負を並べた 1 人用モードです。

- **相手の並びは始めるときに一度だけシャッフルして決めます。**
  一度当たった相手が二度出てこないのは、毎回引き直して重複を弾いているからではなく、
  最初に決めた並びを最後まで使っているからです（引き直し方式だと残りが減るほど
  空振りが増えるうえ、上限まで戦えるとは限らなくなります）
- **最大 10 戦**（`MAX_BATTLES`）。ロスターが 10 人なので、自分と同じキャラも
  相手に入れて 10 戦にしています（同キャラ対決が何戦目に来るかはランダム）
- **負けたらゲームオーバー**。時間切れの引き分けも勝ち抜けにはなりません。
  敗北をやり直しでなかったことにできないよう、アーケード中だけポーズの
  「やり直す」を隠しています
- 次の相手は名前と立ち絵で紹介し、**これから当たる相手は伏せたまま**にしています
  （並びがランダムなのが売りなので、先が見えると引きが弱くなります）
- 紹介画面は **5 秒で自動的に試合が始まります**（ボタンを押せばすぐ始まります）。
  秒読みは `setTimeout` ではなく描画フレームで数えているので、
  **タブが裏に回っている間は止まります**。他の画面を見ている隙に試合が始まって
  1 戦目から死んでいた、が起きません

進行を持っているのは `ArcadeRun` だけで、試合にも DOM にも触りません。
順番の性質（重複しない・上限まで戦える・シードが同じなら再現する）は
`npm test` の「アーケードの組み合わせ」で検証しています。

### 強さは測って決めている

人間の癖を模した相手（ガードで固める / 突っ込む / 飛び込む / 間合いの先端で待つ）との
ラウンド勝率と、**同じ状況で同じ行動を選ぶ割合**（読みやすさ）の両方を見ています。

| | 読みやすさ | 固める | 突っ込む | 飛び込む | 先端待ち | 弾を撒く | 平均勝率 |
|---|---|---|---|---|---|---|---|
| 以前の CPU | 47.0% | 78.4% | 44.5% | 63.6% | 52.9% | **0.0%** | 59.9% |
| 最善手を選ばせた版 | 53.4% | 83.0% | 56.4% | 65.7% | 55.2% | 0.0% | 65.1% |
| 手を混ぜた版 | 38.7% | 80.6% | 52.2% | 68.7% | 61.3% | 2.0% | 65.7% |
| **弾に対応した版（現在）** | **37.9%** | **88.0%** | **65.0%** | **71.5%** | **71.1%** | **31.1%** | **73.9%** |

読みやすさは低いほど読まれにくい指標です。2 行目が「勝率は上がったのに弱く感じる」版でした。

**「弾を撒く」相手には以前の CPU の勝率が 0.0% でした。** 弾をガードも回避もせず、
まっすぐ歩いて当たりに行っていたためです。ここを直したついでに入れた
「危険が目前なら決めた行動を打ち切って考え直す」（`_mustRethink()`）が
弾以外にもよく効き、固める相手・突っ込む相手への勝率も大きく伸びました。

難易度の差も開いています（`hard` vs `normal` が 53.9% → 59.3%、`normal` vs `easy` は 61.7%）。
同一設定同士の対戦は 49〜51% で、測定に偏りが無いことも確認しています。

### 設計の要点

**ゲームのルールは `src/game/` に閉じています。** ここは

- 実時間（`Date.now` / `performance.now`）を見ない
- `Math.random` を使わない（乱数は `core/rng.js` 経由）
- 画像サイズなど描画側のデータに依存しない

を守っているため、**同じ入力列からは必ず同じ試合になります**。
この性質があるおかげで、CPU 戦・ローカル対戦・オンライン対戦・リプレイを
すべて同じコードで扱えます。

## 技・キャラを追加する

### 技を足す

`src/game/characters/*.js` の `moves` にデータを 1 つ足すだけです。
状態遷移のコードには手を入れません。

```js
uppercut: {
  label: '昇竜',
  anim: 'attack2',        // アトラスのアニメ名
  total: 44,              // 全体フレーム（60fps）
  animFps: 14,            // 省略すると total に引き伸ばして再生
  hits: [{
    start: 8, end: 14,                        // 判定が出る区間（両端含む）
    box: { x: 20, y: 60, w: 120, h: 170 },    // 足元原点・前方向が正・上が正
    hitstun: 30, hitstop: 10,                 // damage は不要（当たれば即死）
    launch: { y: 11 },                        // 打ち上げる
  }],
  motion: [{ start: 6, end: 14, vy: 12 }],    // 自分の移動（書いた成分だけ上書き）
  chains: [{ from: 20, to: 38, button: 'attack', move: 'finisher' }], // 連携先
},
```

空中技は、キャラ定義の `airAttackMove` / `airSkillMove` に技 id を書けば
ジャンプ中のボタンに割り当たります。着地で打ち切られるので、
`landLag` で外したときの隙を決めてください。

キャラ定義に `airChainLimit`（数値）を書くと、**空中で技から技へ繋げる回数**に
上限が付きます。数えるのは `chains`（自分でボタンを押した繋ぎ）だけで、
`onEnd` / `onHit` の自動的な繋ぎは数えません。**地面に着いたときだけ数え直す**ので、
跳び直さないと戻りません。地上の連携は押し出しで自然に間合いが切れますが、
空中にはその歯止めが無いので、繋ぎ放題にしたくないキャラだけが持ちます
（いまは格闘娘の 3 回だけ）。

`motion` は**書いた成分だけ**を毎フレーム上書きします。`vx` を書かなければ
**それまでの横の勢いがそのまま残り**、`vy` を書かなければ重力に任せて落ちます。
`motion` そのものを持たない技は**跳んだ弧をまったく変えません**（格闘娘の飛び蹴りが
これで、上りで出せばそのまま上がり続けます）。逆に `vx: 0` は「勢いを殺す」、
`vy: 0` は「落下を打ち消してその場に留まる」という**指定**です
（同じキャラのかかと落としが、弧で乗った横の勢いを `vx: 0` で切っています）。

絵の流し方は技のフレームとは別に決められます。`animFps` を上げるとアニメは早く
再生し切って、残りは最後のコマで止まります。回転や羽ばたきのように**閉じたループとして
作られたシート**を技の全体フレームより速く回したいときは `animLoop: true` を、
**溜めの絵を見せてから振りたい**ときは `animDelay`（先頭のコマを据え置くティック数）を
足してください（順にキャヴァリアの錐揉み突進・切り抜け）。

`motion` が「技データが決めた動き」なのに対して、**出したあとの行き先を
プレイヤーに選ばせたい**ときは `steer`（{from, to, vx, vy}）を使います。
その区間だけ移動操作が速度になり、`motion` のあとに適用されるので操作が勝ちます。
vx は**世界の向き**（前方向ではない）で、`vy` を書くと入力が無いときは 0
＝ その高さに留まります。忍者の竜巻がこれです。

叩きつけて降りる技には `landImpact`（{shake, dust, radius, hold}）を足せます。
着地した瞬間に足元へ土煙を出して画面を揺らします。`hold: true` を足すと、
そのうえで**land の絵に移らずその技の最後のコマを硬直の間ずっと保持**します。
決めの絵を持つ技（戦闘メイドの天空斬り）で、いちばん見せたいコマが着地で
飛ばされるのを防ぐためのものなので、決めの絵を持たない技（格闘娘のかかと落とし）は
`hold` を付けず、**ジャンプと同じ着地の絵**に任せます。
どちらにしても硬直の長さは `landLag` が決めるもので、`landImpact` は触りません。

`vanish`（{frame, ticks}）を足すと、そのフレームから**姿が消えます**。
消えている間は攻撃とスキルが出せず、相手の攻撃はそのまま当たります（忍者の煙玉）。

`ward`（{frame, ticks}）を足すと、そのフレームから**結界が張られます**。
張っている間に当たった**相手のスキル**（`guardBreak` を持つ技と掴み）は無効化され、
キャラ定義の `wardCounter` に書いた技へその場で移ります（巫女の結界）。
打撃と普通の飛び道具は素通しなので、避ける手段ではなく**返し技**になります。

飛び道具は既定で「前方向」へ飛びますが、`spawns` に `aim: true` を足すと
**その瞬間の相手**へ向かって飛びます。さらに `spread: {c, s}` を足すと、
狙った向きからその回転ぶんだけ開きます（巫女の散り札）。
c / s は回転の cos / sin で、**実行時に三角関数を呼ばないため**に技データ側が
定数として持ちます（同じ入力から必ず同じ試合になることを守るため）。
狙って撃つ空中技には `turnInAir: true` も足してください。空中技は既定で
跳んだ向きのまま出るので、これが無いと背中側の相手を狙ったときに
前を向いたまま弾だけが後ろへ飛びます。

技を出している間ずっと出したい演出は `vfx` に書きます。`spawns` と違って
寿命を持たず、**技が終われば必ず消える**ので、着地で打ち切られる空中技でも
演出だけが残りません（忍者の竜巻の渦）。

**素材の姿勢が技の趣旨と食い違う**ときは `tilt`（{deg, pivot}）で絵だけを傾けられます。
`vfx` と同じで描画側しか読まないので、**判定も移動も傾きません**。
`deg` は正が前のめり（向いている方へ頭を倒す・左向きなら自動で反転）で、
回す中心は既定で腰の高さ（`pivot` ＝ 100）です。足元で回すと体ごと横へ振り出されます。
格闘娘のかかと落としがこれで、**立ったまま足を真上へ上げたコマ**を 50 度寝かせて
「回りながら足を放り出した」姿勢にしています。

**技の途中で傾きを変える指定は用意していません。** 絵は数コマ単位で飛び飛びに動くので、
そこへ 1 ティックずつの連続した回転を重ねると、**コマが変わらない間だけ体が逆向きに
滑って、コマが変わった瞬間に戻ります**（13fps の絵に対して回転は 60 分の 1 秒ごとなので、
4〜5 ティックぶん滑ってから戻る＝ガクつきになります）。傾けっぱなしにしておけば、
技の中で動くのは絵のコマだけです。

主なフィールドは `src/game/moves.js` の先頭にまとめてあります。
`F1` で判定ボックスを表示しながら調整すると早いです。

必殺技コマンド（`↓↘→` など）を足したくなったら、`Fighter._readInput` に
入力履歴の照合を追加し、技データ側に `command` を持たせる形になります。
入力はすでにフレーム単位のビットマスクで扱っているので、履歴を見るだけで実装できます。

### キャラを足す

1. スプライトシートを `SpriteSheetCreater` で出力する
2. `tools/build-assets.ps1` の `$CONFIG` に追加する
3. **そのキャラだけ**焼く（全キャラを焼き直すと数分かかるうえ、
   変わっていないアトラスの中身まで書き換わります）

   ```bash
   powershell -ExecutionPolicy Bypass -File tools/build-assets.ps1 -Only 新キャラ
   node tools/pack.mjs 新キャラ
   ```

   引数を付けなければ全キャラぶん焼きます（`npm run assets`）。
4. `src/game/characters/新キャラ.js` を作り、`characters/index.js` の `ROSTER` に足す

素材の癖は、キャラ定義の 2 つで**描くときだけ**直せます（判定にも移動にも影響しません）。

- `animScale` — その行だけ他より小さく／大きく描かれているとき（剣士の `run`）
- `animFlip` — その行だけ逆を向いて描かれているとき（淫魔の `divekick`）
- `animRanges` — その行に**その状態では使わないコマ**が入っているとき
  （戦闘メイドの `jump`。前半の屈み込みを捨てて空中のコマから流す）

アニメ 1 行だけ**アンカーがずれている**（＝絵の中の本人が足元原点に乗っていない）
ときは、描画側ではなく `tools/build-assets.ps1` の `nudge` で直します。
シート単位の `dx` / `dy` と違って行ごとに効き、単位はワールド単位です
（戦闘メイドの `spin_slash` と `aether_slam`）。切り出し範囲は動かさないので、
どれだけ動かしても絵が欠けることはありません。

必要なアニメは `idle / walk / run / jump / fall / land / guard / crouch / hurt / death`
に加えて、**`grabbed`（掴み技に捕らえられている姿）が全キャラ必須**です。
`npm test` の「絵の対応」が `anims` の全項目をアトラスと突き合わせるので、
足りなければテストが落ちて気づけます。

## アセットのビルド

元のスプライトシートは 1 枚 4〜14MB あり、合計 40MB 近くあります。
そのままでは（特にスマホで）重いので、2 段階で加工しています。

```bash
npm run assets          # 生成（PowerShell + Node）
npm run assets:verify   # 整列を目視確認する画像を .debug に出力
```

**1 キャラだけ焼き直すこともできます。** どちらの段階も id で絞れるので、
キャラを 1 人足すために全キャラを再エンコードする必要はありません。

```bash
powershell -ExecutionPolicy Bypass -File tools/build-assets.ps1 -Only ninja
node tools/pack.mjs ninja
```

| 段階 | スクリプト | やること |
|---|---|---|
| 1 | `tools/build-assets.ps1` | アニメごとに余白を切り詰め、縮小し、1 キャラぶんのアトラス（複数ページ）に詰め直す。**アニメごとにアンカー（足元の位置）を計算して JSON に書く** |
| 2 | `tools/pack.mjs` | WebP に変換（PNG 79MB → **12.1MB**） |

### 焼く解像度（`-Supersample`）

アトラスは **1 ワールド単位 = 2 テクセル**で焼いてあります。マニフェストの
`texelsPerUnit` がその倍率で、描画側（`spritebank.js`）が割り戻すので、
ワールド単位・アンカー・判定は倍率を変えても一切変わりません。

等倍で焼かない理由は、**ゲーム側が拡大して描くから**です。カメラの `zoom` は
画面サイズから決まり、実際の拡大率（`zoom × dpr`）は 1280×720 で 1.41 倍、
1920×1080 で 2.11 倍、Retina ノートでは 3.36 倍に達します
（スマホは 0.87 倍なので等倍以下）。等倍で焼くと PC で全キャラがぼやけます。

2 が上限です。元シートはキャラの身長が 407〜573px しかなく、表示身長の
約 2 倍ぶんしか情報が入っていないので、それ以上に上げても実解像度は増えません。

### ページ分割（`-MaxPagePixels`）

アトラスは 1 キャラ 1 枚ではなく、**8Mpx ごとに複数ページへ分けて**焼きます。
マニフェストの `images` がページ一覧で、各アニメの `page` がその添字です。

分けるのは **iOS Safari が 1 枚あたり約 16.7Mpx（4096×4096）を超える画像を
デコードしないから**です。`-Supersample 2` で 1 枚にまとめると淫魔で 35Mpx に
達し、iPhone だけゲームが動かなくなりました（PC の Chrome は通ってしまうので
気づきにくい）。解像度を落とさずに 1 枚を小さくするのがこの分割です。

分割は詰め方だけの話で、コマ寸法・アンカー・`scale` は 1 枚のときと同じです。
アニメは幅の広い順に並べてから詰めるので、狭いアニメが広いページの余白に
引きずられません。1 アニメ（＝1 行）は分割されないため、行 1 本だけのページは
上限を超えることがあります（今の最大行は約 2.7Mpx なので実際には起きません）。

1 キャラは複数のシートに分かれています（例: `swordsman` / `swordsman_extra` /
`swordsman_crouch`）。シートを増やしたら `tools/build-assets.ps1` の `$CONFIG` の
`sheets` に 1 行足してください。中のアニメは自動で全部拾われます。

**アンカーが要点です。** 通常シートと `_extra` / `_crouch` シートではコマ寸法が
違い（485×485 と 560×614 など）、キャラの描かれている位置もずれています。
そのまま並べると、ガードした瞬間にキャラが浮いたり横にずれたりします。
そこで各シートについて

- **接地ライン**: 行ごとの不透明ピクセル数から足の裏を検出（下に垂れた刃先やマントを無視する）
- **左右位置**: シルエットのアルファ加重中央値（外に伸びた剣に引っ張られない）

を求め、その点を基準に全アニメを描き直しています。実測ではキャラの実寸は
シート間で 2% 以内に収まっていたので、拡大縮小の補正は不要でした。

**移動しながら撮ったループだけは、コマごとに位置を止め直します**
（`$CONFIG` の `stabilizeX` / `stabilizeY`）。飛行の絵は撮っている間にキャラが
画面を横切ったり昇ったりするので、シート 1 枚ぶんのアンカーでは追いつきません。
ループが頭に戻るたびにその移動ぶんが戻り、横揺れや**ぴょこぴょこした上下動**に
なります（キャヴァリアのダッシュは実測で 1 ループあたり 29 単位 ＝ 身長の 14% 落ちていました）。

揃える先が縦横で違うのは意図的です。**横は「シートのアンカー」**に寄せます
（どのアニメでも立ち位置は同じであってほしい）。**縦は「そのアニメ自身の平均」**に
寄せます（浮いている高さはアニメごとに違ってよく、消したいのは同じアニメの中の
ドリフトだけなので）。補正した量はビルドのログに出ます。

位置を止めても、**脚と翼の開き具合まで最初と最後で揃うわけではありません。**
繰り返すとそこで一度巻き戻って見えるので、そういうアニメはキャラ定義の
`animOnce` に載せて**最後のコマで止め**ます（キャヴァリアのダッシュがこれ）。
走りが閉じたループになっているキャラは今までどおり繰り返します。

元シートの場所を変えた場合は `-Src` で指定できます。

```bash
powershell -ExecutionPolicy Bypass -File tools/build-assets.ps1 -Src D:\path\to\output_sprite
node tools/pack.mjs
```

## オンライン対戦

ゲーム本体は静的ファイルだけで完結しますが、オンライン対戦のときだけ
**中継サーバ**が必要です。詳細は [`server/README.md`](server/README.md)。

```bash
cd server && npm install && npm start   # ws://localhost:8787
```

タイトル →「オンライン対戦」→ キャラ選択 → サーバ URL と合言葉を入力。
同じ合言葉の 2 人が繋がると試合が始まります。

判定やダメージ計算はサーバでは**行いません**。2 台のブラウザが同じ入力から
まったく同じシミュレーションを走らせます。サーバの仕事は
「2 人を組ませる」「乱数シードを配る」「入力を横流しする」の 3 つだけなので、
安いレンタルサーバでも十分です。

> GitHub Pages は https 配信のため、接続先は **`wss://`（TLS）が必須**です。
> nginx などでリバースプロキシして TLS を終端してください。

### 通信方式を差し替える

現在は**入力遅延ロックステップ**（`src/net/session.js` の `LockstepSession`）です。
実装が小さく確実ですが、回線遅延がそのまま操作感に出ます。

ロールバックへ移行する足場はすでにあります。

- `Simulation.save()` / `load()` — 状態の巻き戻し
- `Fighter.save()` / `load()` — 素の値だけのスナップショット
- シミュレーションが実時間・`Math.random` に依存していないこと

`LockstepSession` を差し替えるだけで済み、ゲームのルールには手を入れません。
WebRTC の P2P にしたい場合も、`src/net/transport.js` に同じ形のクラスを足すだけです。

## 既知の制限

- **2 人対戦（同一端末）はキーボード / ゲームパッド向け**です。スワイプ操作は 1P のみを操作します
- **しゃがみ専用の技はありません**。しゃがみからボタンを押すと立ち技が出ます
  （しゃがみ攻撃のスプライトシートが用意できたら、`crouchAttackMove` を足す形で追加できます）
- 必殺技コマンド入力は未実装（上の「技を足す」参照）
- 効果音・BGM はありません
- WebP を使っているため、2020 年より前のブラウザでは画像が表示されません
