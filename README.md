# 一発当たったら即死な2D格闘

スマホ・PC 両対応のブラウザ 2D 対戦格闘ゲーム。
ビルド不要の静的サイトなので、**リポジトリをそのまま GitHub Pages に公開すれば動きます。**

- **先に技を通した方が勝ち。** 攻撃が当たった時点で体力は全部消えます
- 5 キャラクター（剣士 / 狂戦士 / 魔法使い / 女子高生 / 淫魔）
- CPU 戦 / 同一端末での 2 人対戦 / オンライン対戦
- キーボード・ゲームパッド・画面タッチに対応
- 技はすべてデータ定義。技もキャラも追加しやすい構造

---

## ルール

**攻撃が当たったらその時点で負けです。** 多段技なら 1 打目でも最終打でも同じで、
かすった瞬間に勝敗が決まります。ダメージ量という概念がありません
（技データの `damage` は技の重さの目安として残してありますが、計算には使いません）。

ただし当たった瞬間に消えると何が起きたか分からないので、演出だけ最後まで見せます。

1. 当たった時点で体力を 0 にして、内部的に「致命傷（`doomed`）」を立てる
2. **のけぞりは普通に取る** — 残りの段もそのまま当たり、ヒット数が伸びていく
3. **コンボが途切れた瞬間に崩れ落ちる**

**血しぶきが出るのは 3. の崩れ落ちる瞬間だけ**です。コンボ中の 1 打 1 打は
従来どおり火花で、決着したことが一目で分かるようにしてあります。

つまり 4 段技が全部当たれば「4 HITS」まで見えてから倒れ、
1 段目だけかすったなら、そののけぞりが解けたところで倒れます。

避ける手段は **2段ジャンプ / しゃがみ / ダッシュ / ガード** の 4 つ。
**ガードは通ります**が、**スキルはガードごと崩す**ので守り一辺倒では勝てません。
**ジャンプ中も攻撃・スキルが出せます**（それぞれ専用の空中技）。

ただし**淫魔の吸血だけは掴み技**で、避け方が他と違います。

- 他のスキルはガードを崩す打撃なので、判定さえ届けば**空中の相手にも当たります**
- **掴みは相手が空中にいると絶対に当たりません**（`hit.grab`）。
  ガードでは防げないので、**跳ぶことが唯一の答え**になります

つまり淫魔戦だけは「ガードで固めて待つ」が成立しません。詳しくは
[キャラクターと技](#キャラクターと技) の淫魔の項を見てください。

**しゃがみは魔法使いの照射ビームをくぐるための手段**です。
ビームは杖の先（足元から 156）を中心に上下 49 ＝ 地上 107〜205 を薙ぐので、
しゃがんでやられ判定が 100 まで縮めばその下を通せます。
ビームはガード不能なので、しゃがみが唯一の答えです。
沈むのにも立ち上がるのにも `CROUCH_TICKS` かかるため、読んで先に構える必要があります
（打撃は判定が低いところまで出ているので、しゃがんでも当たります）。

照射は**撃つまでに 1 秒（60 フレーム）の溜め**があり、その間ずっと
**足元に魔法陣**が回っています。これが「これから撃つ」の合図で、
見てからしゃがんでも十分間に合う長さにしてあります。
逆に言えば、魔法使いは 1 秒間まったくの無防備になります。

さらに魔法使いは、遠距離で完結させられないように 2 段階で制限しています。

- **ホーミング弾は場に 1 発まで**（`PROJECTILES.bolt.maxAlive`）。
  撃った弾が消えるか当たるまで次が出ないので、弾幕で近づけないようにはできません
- **照射を構えた瞬間、場に出ている自分の弾は消えます**
  （技データの `clearsOwnProjectiles`）。弾で足止めしてから照射、という
  重ねがけが通らないので、弾を撒くか照射を撃つかを選ぶことになります

決着が一瞬なので、1 ラウンド 45 秒・**3 本先取**にしてあります
（`src/game/constants.js` の `ROUND_TIME` / `ROUNDS_TO_WIN`）。

## 動かす

### そのまま公開する（GitHub Pages）

リポジトリの **ルート** をそのまま配信するだけです。

1. GitHub にプッシュ
2. Settings → Pages → Source を `Deploy from a branch`、ブランチを `main` / フォルダを `/ (root)` に設定
3. 数分後 `https://<ユーザー名>.github.io/<リポジトリ名>/` で遊べます

`assets/`・`src/`・`index.html`・`styles.css` があれば動きます。
`tools/`・`server/`・`node_modules/` は配信されても実害はありませんが、無くても構いません。

### ローカルで確認する

ES モジュールは `file://` では読み込めないため、簡易サーバ経由で開いてください。

```bash
npm install     # 画像変換用の sharp が入ります（ゲーム自体には不要）
npm run serve   # http://localhost:8080/
```

## 操作

| | 移動 | ジャンプ | しゃがみ | 攻撃 | スキル | ガード |
|---|---|---|---|---|---|---|
| **1P キーボード** | `A` / `D` | `W` | `S` | `J` | `K` | `L` |
| **2P キーボード** | `←` / `→` | `↑` | `↓` | `,` | `.` | `/` |
| **ゲームパッド** | スティック・十字 | `Y` | 十字下・スティック下 | `A` | `X` | `B` / `L1` |
| **スマホ** | 左半分を横へ小さく/大きく | 左半分を上/斜め上（空中はどの向きでも） | 左半分を下 | 右半分をタップ | 右半分を敵の方へ | 右半分を下 |

- **ダッシュ**: 同じ方向を素早く 2 回押す（スマホは横に大きくスワイプ）
- **ジャンプは自分の身長ぶん跳べます**（`jumpVyForHeight()` で各キャラの身長から逆算）
- **2段ジャンプ**: 空中でもう一度ジャンプ。方向を入れずに跳ぶと真上へ跳び直して軌道をずらせます。
  2段目は高さを稼ぐためではなく軌道をずらすためのものなので、1段目より低く跳びます
- **しゃがみ**: 押している間だけ沈み、離すと立ち上がります。移動はできません。
  やられ判定は姿勢に合わせて少しずつ縮むので、押した瞬間にビームをくぐれるわけではありません
- **歩き中は常に相手を向きます。** 後ろに下がるときは歩きモーションが逆再生されます
- **ダッシュ中だけは進んでいる方向を向きます**
- **スキル**はガードを崩せる技。当たれば大きいですが、外すと隙が大きい
- **空中で攻撃 / スキル**を押すと専用の空中技が出ます。空中技は**着地した時点で打ち切られ**、
  技ごとに決めた着地硬直（`landLag`）に入ります
- `Esc` ポーズ / `F1` 判定ボックス表示（技の調整用）

### スマホはボタンではなくスワイプ

画面を左右に割って、**左半分が移動・右半分が攻撃**です。ボタンは置いていません。
押す場所を目で探す必要がなく、画面のどこを触っても効くので、視線をキャラから外さずに操作できます。

| 左半分（移動） | | 右半分（攻撃） | |
|---|---|---|---|
| 横に**小さく**スワイプ | 歩く | **タップ** | 攻撃 |
| 横に**大きく**スワイプ | 走る | **相手のいる方へ**フリック | スキル |
| 斜め上スワイプ | 斜めジャンプ | 下へフリック | ガード |
| 真上スワイプ | 垂直ジャンプ | | |
| 下スワイプ | しゃがみ | | |
| **空中はどの向きでも** | 2段ジャンプ | | |

- **指を触れている間、その入力が続きます**（離すと止まる）。走りも同じで、
  指を置いたままなら技や被弾で途切れても走りに戻ります
- **指を離さずに続けて操作できます。** 弾いて指を戻せば次のスワイプを受け付けるので、
  「歩いてから走りに上げる」も「走ったまま上へ弾いて斜めジャンプ」も 1 タッチで繋がります
- **空中ではどの向きへ弾いても 2段ジャンプ**になります。横へ弾けばその方向へ跳ぶので、
  真上を狙う必要はありません。空中では横入力で速度が変わらない
  （跳んだ瞬間の向きで軌道が決まる）ので、横スワイプをそのままにしておくと
  空振りになるためです。空中の移動手段はジャンプだけ、という前提に合わせています
- **左右は同時に使えます**（左の親指で走りながら右の親指で技）
- **攻撃は指を離した時点で出ます。** 押した瞬間に出す方が速いのですが、
  それだとスキルやガードのスワイプも「まず押す」ので毎回攻撃が暴発します。
  一撃で決まるゲームなので、暴発の方が数フレームの遅延より痛いという判断です。
  同じ理由で、**弾いた後に指を離しても攻撃は出ません**（タップとは区別しています）
- 置きっぱなしの指を離しただけで技が出ないよう、タップと見なす接触時間には
  上限（`TAP_MAX_MS`）があります
- スキルが**左右ではなく前後**で決まるのは、相手が回り込んでも
  「フリックした向き」と「出る技」が食い違わないようにするためです。
  相手に背を向ける方向のフリックは割り当てていません
- いま何が入っているかは画面下のラベルに出ます。何もしていない間は操作の凡例が薄く出ます

**認識に使っているのは向きと距離だけで、速さは見ていません。**
ゆっくり滑らせても素早く弾いても同じ扱いになります（「スワイプ」と「フリック」で
挙動は変わりません）。速さを条件にすると「強く弾いたつもりが出ない」が起きやすく、
一撃で決まるこのゲームでは取りこぼしの方が痛いためです。

判定値は `src/core/gestures.js` の `SWIPE` に集めてあります。角度は横を広く
（各 90°）・真上と真下を狭く（各 60°）取ってあり、横に大きく弾いて指が弧を描いても
走りとして扱われます。歩きと走りの境目は `RUN`（弾いた距離）です。

### キャラクターと技

| キャラ | 攻撃 | スキル（ガード崩し） | 空中攻撃 | 空中スキル |
|---|---|---|---|---|
| **剣士** | 横切り → 続けて攻撃で **盾切り** | タックル（溜めてから突進） | 飛び斬り | 急降下斬り |
| **狂戦士** | 乱舞（4 段の連続斬り） | 突き（長い踏み込み） | 空中乱舞（2 段） | かかと落とし |
| **魔法使い** | ホーミング弾（場に**1発**まで） | 極太照射ビーム（**1秒溜め**） | 降魔弾（斜め下へ撃ち落とす） | 浮遊照射（**1秒溜め**） |
| **女子高生** | カメラレーザー（真っ直ぐ飛ぶ） | **彼氏突進**（指をさすと彼氏が走ってくる） | 空撮レーザー（斜め下へ） | 上から指さし |
| **淫魔** | 引っ掻き → 続けて攻撃で **2 段目**（1 段目を振り切ってから出る） | **吸血**（掴み。ガード無効／空中には当たらない） | 翼叩き（横に薙ぐ） | 急降下（判定は**真下**） |

剣士と狂戦士の空中スキルは斜め下へ落ちる突進技で、外すと着地の隙が大きくなります。

**女子高生は自分の技に打撃判定をひとつも持ちません。** 当てるのはスマホから出る
レーザーと、スキルで呼ぶ彼氏だけです。「技を出す」と「当たる」が離れているのが持ち味で、
弱点でもあります。

- **カメラレーザー**は追尾しないぶん速く、真っ直ぐ飛びます。発射位置は
  **掲げたスマホのカメラ**（足元から x=58 / y=170）で、スマホ本体の前端より
  少し先に置いてあります（本体の中心から出すと光が被って手元が潰れます）。
  頭の高さを薙ぐので、**しゃがめばくぐれます**
- **彼氏突進**は、指をさすと**後ろ 300 から彼氏が走ってきて**相手に突っ込みます。
  呼んでから届くまでが長いぶん、当たればガードごと崩してダウンを奪います。
  **当てても消えず、そのまま走り抜けていきます**（判定は一度当てたところで切れるので、
  走り抜けながら何度も当たることはありません）。外しても走り抜けるだけで、
  その間こちらは丸腰です。彼氏は場に 1 人までなので連呼できません。
  **空中で呼んでも彼氏は地面を走ります**（`groundBound`）

彼氏は飛び道具の枠（`PROJECTILES.boyfriend`）で動かしていますが、`style: 'sprite'` を
持つので専用のアトラス（`assets/characters/boyfriend.*`）で描かれます。
判定も丸ではなく人ひとりぶんの箱です（飛び道具の `box`）。
走りから突進への切り替えは**相手との距離**で決めています（`tackleRange`）。
経過フレームで切り替えると、呼んだ位置によって跳び込む間合いがずれてしまうためです。

**突進のシートは 1 回ぶんの動きなので、繰り返しません。** 切り替えは距離で決めますが、
**コマ送りは距離ではなく、突進に入ってからの経過フレーム**（`lungeAge`）で進めます。
コマまで距離で決めると、相手を追い越したあとに距離が開いてコマが逆戻りし、
2 周したように見えてしまいます。出し切ったら走りに戻って、そのまま走り抜けます。

#### レーザーの描き方（`_drawLaser`）

血しぶきとは逆に、**ここは加算合成が正しい**判断になります。血は光らないので
`source-over` で描いていますが、レーザーは光そのものなので、背景に足し合わさらないと嘘になります。

| | やっていること | これが無いと |
|---|---|---|
| **断面を楕円の放射グラデーションに** | 単位円のグラデーションを長円へ引き伸ばす | 帯を重ねると段が見えて「板」になる |
| **芯を丸端の線で描く** | `lineCap: 'round'` の 1 本線 | 端が角ばって、切り落とした棒に見える |
| **芯だけ白く飛ばす** | 中心の彩度を捨てて白にする | 明るいだけの色帯になる。強い光は白飛びする |
| **進行方向へ伸ばして向ける** | 1 フレーム進む距離ぶん尾を引き、速度ベクトルの角度に回す | 止まって見える／斜めに撃っても光は水平のまま、という食い違いが出る |
| **尾を発射点より後ろへ伸ばさない** | 飛んだ距離を上限にする | 撃った直後に長い尾が出て、スマホと手に光が被る（＝そこから出ているように見えない） |

判定そのものは軸に沿った箱のままなので、斜めに撃ったときは見た目と判定が
厳密には一致しません（見た目を優先しています）。

魔法使いの**浮遊照射**だけは毛色が違い、**空中でぴたりと止まって**極太ビームを撃ちます。
止まる高さは「跳んでから何フレーム目に押したか」でそのまま決まるので、

- **低空で撃つ** → 地上の相手を薙ぎ払う
- **高めで撃つ** → 飛んできた相手を撃ち落とす

という撃ち分けになります。そのぶん、外すと空中に静止した的になります。

#### 淫魔（掴みと飛行）

他の 4 キャラが「ガードは崩せるが、跳ばれると弱い」で揃っているのに対して、
淫魔だけが逆を向いています。**ガードに勝って、ジャンプに負ける**キャラです。

**吸血（掴み）** は判定に `grab: true` を持つ唯一の技で、他の攻撃とは別の経路を通ります。

- **ガードを見ません。** 固めている相手にもそのまま通ります
- **相手が空中にいると当たりません**（`sim.js` の `_resolveHits`）。
  跳ぶことが唯一の回避手段です
- 捕らえると `onHit` で保持の技（`drainHold`）へ移り、相手は `STATE.GRABBED` になります。
  位置・向きとも固定され、**掴んだ本人以外からは無敵**です
- 吸い切ると最後の 1 打で放り投げ、叩きつけたところで決着します。
  掴んだ側が途中で技を中断されると、相手はその場で落とされます
- **外すと総フレームぶん硬直します。** 掴みは当たれば決まりなので、
  リスクは全部「外したとき」に寄せてあります

保持位置は技データの `grabHold`（足元原点・前方向が正）で決めます。掴まれた側は
各キャラの `grabbed` アニメで描かれるので、**ロスター全員が `anims.grabbed` を持つ必要**が
あります（同キャラ戦があるので淫魔自身も含む）。描画は y 順ではなく
**掴まれている側を必ず手前に**描いています（`renderer.js`）。
吸血は相手に顔を埋めて吸う画なので、淫魔の顔が相手の陰に入るのが正しい姿です。

**飛行**はキャラ定義の `flight` で表します。

```js
airJumps: 4,                                  // 1段目(地上)と合わせて 5 段
flight: { fromJump: 3, ticks: 42, speed: 3.8 },
```

- **1・2 段目は他のキャラと同じ跳び上がり**です
- **3 段目から先は跳び上がらず、その高さに留まります**（`ticks` フレーム）。
  左右入力があれば `speed` でその高さのまま動けます
- **高度は上がりません。** 高さを稼ぐのはあくまで 1・2 段目で、
  飛行は「跳んだ高さを保ったまま位置を選び直す」ための手段です
- 技を出すと滞空は切れます。滞空 → 急降下、という繋ぎが主な使い道です

重力の打ち消しは、滞空中は毎ティック `vy` を 0 に戻すだけで済ませています
（`_integrate` はそのあとに走るので、落下ぶんが積もりません）。
魔法使いの浮遊照射が使っている技データの `vy: 0` と同じ考え方です。

```

  main.js           起動と画面遷移。ブラウザの都合を知る唯一の場所
  core/
    loop.js         固定 60fps のゲームループ
    input.js        キーボード/スワイプ/パッド → 入力ビットマスク
    gestures.js     スワイプの認識（DOM を知らない純粋な計算）
    assets.js       アトラス読み込み
    rng.js          決定的な擬似乱数
  game/             ← ゲームのルール。DOM も時計も知らない
    constants.js    単位系・ボタン定義
    sim.js          試合のシミュレーション本体
    fighter.js      キャラ1体の状態機械
    moves.js        技データの定義と補助
    projectiles.js  飛び道具
    ai.js           CPU（技データから間合いと発生を割り出して判断する）
    characters/     キャラ定義（← 増やすのはここ）。index.js の ROSTER に足す。
                    技から出てくるスプライト（彼氏）は EXTRA_SPRITE_IDS に書く
  render/           描画。sim を読むだけで書き換えない
  net/              通信層（transport / session）
  ui/screens.js     メニュー画面
tools/              アセット生成と検証（開発時のみ）
server/             オンライン対戦用の中継サーバ（任意）
assets/characters/  生成済みのスプライトアトラス（配信対象）
```

### 血しぶきの作り方（`renderer.js`）

決着の演出なので、ここだけは作り込んであります。安っぽく見えないために効いているのは
主に次の 4 つで、いずれも `_drawBlood` / `_bloodParticles` の中にあります。

| | やっていること | これが無いと |
|---|---|---|
| **粒径をべき分布に** | `0.32 + u^4.6 * 3.1`。ほとんどが微細な粒で、大粒はごく少数 | 同じ大きさの丸が並んで、一気に嘘くさくなる |
| **空気抵抗** | `dv/dt = -k・v - g` の解析解で飛ばす。`k` は粒径に反比例 | 全部が同じ形の放物線を描く。抵抗があると小粒はその場に落ち、大粒だけが遠くまで届く |
| **着地したら床の染みに** | 着地時刻を粒ごとに先に解いておき、以降は染みとして描く | 落ちた血が消えてしまう |
| **加算合成を使わない** | `source-over` の暗い静脈血。薄く伸びた部分だけ少し明るく | 血が光る。光った瞬間に嘘になる |

粒ごとの初期値は描画側の `WeakMap` に持っています。エフェクト自体
（＝シミュレーションのデータ）には書き戻さないので、ロールバックしても壊れません。
飛沫が一番多いフレームでも `render()` は約 4.8ms（60fps の予算 16.7ms）です。

### CPU の考え方（`ai.js`）

一発当たったら即死なので、手数を増やすより **振るか振らないかの判断**がほぼ全部を決めます。
そこで CPU は次の 3 つを土台にしています。

| | やっていること | これが無いと |
|---|---|---|
| **技の性能を技データから読む** | 判定リーチ・**前進量**・発生フレームを `profileOf()` で割り出し、届く間合いでしか振らない | 数値を手で持つと技を調整したときに置いていかれる。剣士のタックルは判定リーチ 142 でも 182 前進するので、前進を見ないと「実際は届く間合い」で振らなくなる |
| **相手の隙を数える** | 空振りの戻り・着地硬直・のけぞり・ガード硬直を `_openFrames()` でフレーム数として出し、自分の発生が間に合うときだけ差し込む | 手当たり次第に振って差し返される。突っ込んでくる相手への勝率が実測で 11 ポイント変わりました |
| **ガードは崩す / 崩されない** | 固める相手にはスキル（ガード貫通）、届かない技にはガードを固めない | 固めるだけの相手を崩せない。逆に届かない技へガードを固めると差し込む機会を捨てる |
| **飛んでくる弾を捌く** | `sim.projectiles` を見て、**相対速度**で到達時間を出し、ガードで受ける | 弾は撃った本人と切り離して飛ぶので、技のモーションだけ見ていると気づけない。魔法使いを相手にすると弾に向かって歩いて当たりに行く |

**飛び道具まわりは直感が外れます。** 実測して分かったこと。

- **ただ跳ぶのは逆効果。** 魔法使いの弾は杖の先（足元から 248）から出て
  追尾しながら降りてくるので、跳ぶと弾の高さへ自分から入ります。
  しかも空中はガードできないので、外したらそのまま食らいます。
  **ただし 2段ジャンプなら避けられます**（下記）
- **しゃがみも効きません。** 弾はしゃがんだぶん狙いを下げ直してきます
  （`homeToward()` がやられ判定の中心を狙うため）。効くのは照射ビームだけです
- **弾を持つ相手には跳ばない。** 滞空は自分の身長ぶんで 50 フレーム超あり、
  弾の発生は 11 フレーム。跳んだ時点で弾が無くても、空中で撃たれて終わります。
  実測では、跳んで弾に当たった 36 回のうち 35 回が「跳んだ時点では弾が無かった」ケースでした
- **到達時間は相対速度で見る。** 弾の速さだけで割ると、弾に向かって走っているとき
  倍近く遅く見積もり、気づいたつもりで間に合いません。これが被弾の主因でした

つまり弾への基本の答えはガードです（弾は `guardBreak` を持たないので確実に止まります）。
反応し始める距離も実測で決めました。短いと受け損ない（到達 14 フレームで反応 → 勝率 0%）、
長いと弾を見るたびに固まって近づけません（60 フレーム → 4%）。34 フレームが一番受けられました。

#### 2段ジャンプでホーミング弾を避ける

ガード以外にもう一つ答えがあります。総当たりで探して見つけた型です。

> **真上に跳ぶ → 弾が 145px まで近づいたら「前へ」跳び直す** … 成功率 **7 割**

1段目だけでは 0〜7% しか避けられず、**避けているのは 2段目**です。
弾は `turnRate` が低くて曲がりきれないので、間近で軌道を変えると置いていけます。
2段目が前方向なので、避けながら間合いも詰まります。

2段目の合図に**残りフレームではなく弾との実距離**を使うのが要点でした。
曲がる弾は到達時間の見積りが当てにならず、残りフレームで合わせると成功率は 14% まで落ちます。

跳び始める窓にも上限が要ります（`DODGE_ARM_MAX`）。早く跳びすぎると弾が来る前に
着地してしまい、2段目を弾に合わせられません。

**溜め技の扱いにも注意が要ります。** 魔法使いの照射は溜めの段階では判定を 1 つも持たず、
`onEnd` の先に本体があります。さらに溜めは演出用の魔法陣を `spawns` に出すので、
これを発生フレームと取り違えると「発生 0 の技」だと思い込んで**密着で溜め始めて的になります**。
`isProjectile()` で実弾だけを見るようにしてあります。

**最善手を毎回選ばせてはいけません。** 一度そう作ってみたところ、勝率は上がったのに
遊ぶと弱く感じるようになりました。同じ状況でいつも同じ答えを返すので、
数ラウンドで読まれて対策されるからです。原因は測り方にもありました
（ベンチの相手は学習しないので、読みやすさが罰されない）。

そこで `think()` は状況ごとに**有効な手を重み付きで並べ、そこから選ぶ**形にしています。

- 「相手の技が来ている」なら ガード / 跳んで越える / 下がって空振りにする /
  しゃがんでくぐる / 発生で勝てるなら割り込む
- 「相手に隙がある」なら 打撃で差し込む / スキルで差し込む / 走って詰める / 様子見
- 「間合い争い」なら 振る / 崩す / 歩いて詰める / 走って詰める / 飛び込む / 待つ / 下がる

**逃げる手には時間の裏付けを付けています。** 跳ぶ・下がるは動き出しに時間がかかるので、
判定が出るまでの残りフレーム（`_framesUntilHit()`）が足りているときだけ候補に出します。
ここを見ないと「逃げようとして食らう」が増えて、実測で 5 ポイント落ちました。

さらに **直前と同じ手は重みを落とし**、数秒ごとに切り替わる**気分**
（攻め / 守り / ふつう）で偏りを揺らしています。同じ距離でも局面によって答えが変わるので、
「この間合いならこう来る」と読み切られにくくなります。

難易度は `DIFFICULTY` の 3 段（`easy` / `normal` / `hard`）で、
各手の重みと `hold`（決めた行動を引きずる時間の倍率）を変えています。
弱い設定ほど長く引きずるので、状況の変化に置いていかれます。
CPU 戦は `hard` を使っています（`src/main.js` の `new CpuController(1, 'hard')`）。

### 強さは測って決めている

人間の癖を模した相手（ガードで固める / 突っ込む / 飛び込む / 間合いの先端で待つ）との
ラウンド勝率と、**同じ状況で同じ行動を選ぶ割合**（読みやすさ）の両方を見ています。

| | 読みやすさ | 固める | 突っ込む | 飛び込む | 先端待ち | 弾を撒く | 平均勝率 |
|---|---|---|---|---|---|---|---|
| 以前の CPU | 47.0% | 78.4% | 44.5% | 63.6% | 52.9% | **0.0%** | 59.9% |
| 最善手を選ばせた版 | 53.4% | 83.0% | 56.4% | 65.7% | 55.2% | 0.0% | 65.1% |
| 手を混ぜた版 | 38.7% | 80.6% | 52.2% | 68.7% | 61.3% | 2.0% | 65.7% |
| **弾に対応した版（現在）** | **37.9%** | **88.0%** | **65.0%** | **71.5%** | **71.1%** | **31.1%** | **73.9%** |

読みやすさは低いほど読まれにくい指標です。2 行目が「勝率は上がったのに弱く感じる」版でした。

**「弾を撒く」相手には以前の CPU の勝率が 0.0% でした。** 弾をガードも回避もせず、
まっすぐ歩いて当たりに行っていたためです。ここを直したついでに入れた
「危険が目前なら決めた行動を打ち切って考え直す」（`_mustRethink()`）が
弾以外にもよく効き、固める相手・突っ込む相手への勝率も大きく伸びました。

難易度の差も開いています（`hard` vs `normal` が 53.9% → 59.3%、`normal` vs `easy` は 61.7%）。
同一設定同士の対戦は 49〜51% で、測定に偏りが無いことも確認しています。

### 設計の要点

**ゲームのルールは `src/game/` に閉じています。** ここは

- 実時間（`Date.now` / `performance.now`）を見ない
- `Math.random` を使わない（乱数は `core/rng.js` 経由）
- 画像サイズなど描画側のデータに依存しない

を守っているため、**同じ入力列からは必ず同じ試合になります**。
この性質があるおかげで、CPU 戦・ローカル対戦・オンライン対戦・リプレイを
すべて同じコードで扱えます。

## 技・キャラを追加する

### 技を足す

`src/game/characters/*.js` の `moves` にデータを 1 つ足すだけです。
状態遷移のコードには手を入れません。

```js
uppercut: {
  label: '昇竜',
  anim: 'attack2',        // アトラスのアニメ名
  total: 44,              // 全体フレーム（60fps）
  animFps: 14,            // 省略すると total に引き伸ばして再生
  hits: [{
    start: 8, end: 14,                        // 判定が出る区間（両端含む）
    box: { x: 20, y: 60, w: 120, h: 170 },    // 足元原点・前方向が正・上が正
    hitstun: 30, hitstop: 10,                 // damage は不要（当たれば即死）
    launch: { y: 11 },                        // 打ち上げる
  }],
  motion: [{ start: 6, end: 14, vy: 12 }],    // 自分の移動
  chains: [{ from: 20, to: 38, button: 'attack', move: 'finisher' }], // 連携先
},
```

空中技は、キャラ定義の `airAttackMove` / `airSkillMove` に技 id を書けば
ジャンプ中のボタンに割り当たります。着地で打ち切られるので、
`landLag` で外したときの隙を決めてください。

主なフィールドは `src/game/moves.js` の先頭にまとめてあります。
`F1` で判定ボックスを表示しながら調整すると早いです。

必殺技コマンド（`↓↘→` など）を足したくなったら、`Fighter._readInput` に
入力履歴の照合を追加し、技データ側に `command` を持たせる形になります。
入力はすでにフレーム単位のビットマスクで扱っているので、履歴を見るだけで実装できます。

### キャラを足す

1. スプライトシートを `SpriteSheetCreater` で出力する
2. `tools/build-assets.ps1` の `$CONFIG` に追加する
3. `npm run assets` を実行
4. `src/game/characters/新キャラ.js` を作り、`characters/index.js` の `ROSTER` に足す

必要なアニメは `idle / walk / run / jump / fall / land / guard / crouch / hurt / death`
に加えて、**`grabbed`（淫魔に掴まれている姿）が全キャラ必須**です。
`npm test` の「絵の対応」が `anims` の全項目をアトラスと突き合わせるので、
足りなければテストが落ちて気づけます。

## アセットのビルド

元のスプライトシートは 1 枚 4〜14MB あり、合計 40MB 近くあります。
そのままでは（特にスマホで）重いので、2 段階で加工しています。

```bash
npm run assets          # 生成（PowerShell + Node）
npm run assets:verify   # 整列を目視確認する画像を .debug に出力
```

| 段階 | スクリプト | やること |
|---|---|---|
| 1 | `tools/build-assets.ps1` | アニメごとに余白を切り詰め、縮小し、1 キャラ 1 枚のアトラスに詰め直す。**アニメごとにアンカー（足元の位置）を計算して JSON に書く** |
| 2 | `tools/pack.mjs` | WebP に変換（PNG 80MB → **12.2MB**） |

### 焼く解像度（`-Supersample`）

アトラスは **1 ワールド単位 = 2 テクセル**で焼いてあります。マニフェストの
`texelsPerUnit` がその倍率で、描画側（`spritebank.js`）が割り戻すので、
ワールド単位・アンカー・判定は倍率を変えても一切変わりません。

等倍で焼かない理由は、**ゲーム側が拡大して描くから**です。カメラの `zoom` は
画面サイズから決まり、実際の拡大率（`zoom × dpr`）は 1280×720 で 1.41 倍、
1920×1080 で 2.11 倍、Retina ノートでは 3.36 倍に達します
（スマホは 0.87 倍なので等倍以下）。等倍で焼くと PC で全キャラがぼやけます。

2 が上限です。元シートはキャラの身長が 407〜573px しかなく、表示身長の
約 2 倍ぶんしか情報が入っていないので、それ以上に上げても実解像度は増えません。

1 キャラは複数のシートに分かれています（例: `swordsman` / `swordsman_extra` /
`swordsman_crouch`）。シートを増やしたら `tools/build-assets.ps1` の `$CONFIG` の
`sheets` に 1 行足してください。中のアニメは自動で全部拾われます。

**アンカーが要点です。** 通常シートと `_extra` / `_crouch` シートではコマ寸法が
違い（485×485 と 560×614 など）、キャラの描かれている位置もずれています。
そのまま並べると、ガードした瞬間にキャラが浮いたり横にずれたりします。
そこで各シートについて

- **接地ライン**: 行ごとの不透明ピクセル数から足の裏を検出（下に垂れた刃先やマントを無視する）
- **左右位置**: シルエットのアルファ加重中央値（外に伸びた剣に引っ張られない）

を求め、その点を基準に全アニメを描き直しています。実測ではキャラの実寸は
シート間で 2% 以内に収まっていたので、拡大縮小の補正は不要でした。

元シートの場所を変えた場合は `-Src` で指定できます。

```bash
powershell -ExecutionPolicy Bypass -File tools/build-assets.ps1 -Src D:\path\to\output_sprite
node tools/pack.mjs
```

## オンライン対戦

ゲーム本体は静的ファイルだけで完結しますが、オンライン対戦のときだけ
**中継サーバ**が必要です。詳細は [`server/README.md`](server/README.md)。

```bash
cd server && npm install && npm start   # ws://localhost:8787
```

タイトル →「オンライン対戦」→ キャラ選択 → サーバ URL と合言葉を入力。
同じ合言葉の 2 人が繋がると試合が始まります。

判定やダメージ計算はサーバでは**行いません**。2 台のブラウザが同じ入力から
まったく同じシミュレーションを走らせます。サーバの仕事は
「2 人を組ませる」「乱数シードを配る」「入力を横流しする」の 3 つだけなので、
安いレンタルサーバでも十分です。

> GitHub Pages は https 配信のため、接続先は **`wss://`（TLS）が必須**です。
> nginx などでリバースプロキシして TLS を終端してください。

### 通信方式を差し替える

現在は**入力遅延ロックステップ**（`src/net/session.js` の `LockstepSession`）です。
実装が小さく確実ですが、回線遅延がそのまま操作感に出ます。

ロールバックへ移行する足場はすでにあります。

- `Simulation.save()` / `load()` — 状態の巻き戻し
- `Fighter.save()` / `load()` — 素の値だけのスナップショット
- シミュレーションが実時間・`Math.random` に依存していないこと

`LockstepSession` を差し替えるだけで済み、ゲームのルールには手を入れません。
WebRTC の P2P にしたい場合も、`src/net/transport.js` に同じ形のクラスを足すだけです。

## 既知の制限

- **2 人対戦（同一端末）はキーボード / ゲームパッド向け**です。スワイプ操作は 1P のみを操作します
- **しゃがみ専用の技はありません**。しゃがみからボタンを押すと立ち技が出ます
  （しゃがみ攻撃のスプライトシートが用意できたら、`crouchAttackMove` を足す形で追加できます）
- 必殺技コマンド入力は未実装（上の「技を足す」参照）
- 効果音・BGM はありません
- WebP を使っているため、2020 年より前のブラウザでは画像が表示されません
